这是什么教程

这不是一份"标准做法"教程——网上那种太多了。这是一份真实制作全程的同步记录:一个零 C++ 基础的游戏策划,在 AI 结对编程的协助下,把一个空 UE 5.8 工程搭成 GAS(Gameplay Ability System)战斗地基的全过程。每一步做了什么、为什么这么做、在哪里翻车、怎么爬出来,全部如实记录。

跟完本教程,你将拥有:一个纳入 Git 版本管理(含 GitHub 远端)的 C++ UE 工程、一套最小但完整的 GAS 骨架(属性表 / 战斗大脑 / 初始化规则 / 标签体系),以及——可能是最值钱的——一本记满真实错误的错题本。

第 0 步 · 版本管理:嵌套双仓库

目标:工程纳入 Git,可回滚;代码、文档和工程自有资产快照推 GitHub,Paragon 原始素材按账号权限重新获取。

为什么是两仓库?

UE 工程的 Content/ 动辄十几 GB,主要由 Paragon 原始资源包构成；本仓库只保存工程自有资产快照。完整盘点与恢复步骤见资产恢复文档:

  • 外层仓库(工程根目录):跟踪代码/文档/配置及筛选后的 ProjectContentSnapshot/Content/ → 推 GitHub
  • 内层仓库(Content/.git):本地跟踪完整工作素材与 Paragon 包历史,不直接推送现有历史

操作

git config --global core.longpaths true        # Windows 必须
# .gitattributes 把 *.uasset *.umap 标记为 binary,防换行符污染
git init -b main                                # 外层,基线提交
cd Content && git init -b main                  # 内层,本地素材历史
# GitHub 建空白公开仓库(不勾 README),git remote add origin ... && git push -u origin main
⚠️ 翻车实录:首次 git push 报 Connection was reset——本机代理(Clash 7897 端口)只对走系统代理的程序生效,git 默认直连。解法:git config --global http.proxy http://127.0.0.1:7897(https 同理)。代理关闭后记得 unset。(错题本 P12)

日常口诀:改代码/文档或快照 → 根目录 commit;动完整素材 → Content 目录本地 commit;Paragon 原包不推 GitHub。

第 1 步 · 工程 C++ 化

目标:纯蓝图工程长出 Source/ 目录,编译通过,编辑器照常打开。

操作

手写 5 个文件(不必走编辑器向导):Source/工程名.Target.cs、工程名Editor.Target.cs、工程名/{工程名.Build.cs, .h, .cpp}。Build.cs 里登记依赖:Core, CoreUObject, Engine, InputCore, EnhancedInput + GAS 三件套 GameplayAbilities, GameplayTags, GameplayTasks。.uproject 启用 GameplayAbilities 与 GameplayStateTree 插件。然后生成工程文件并编译:

# UE5.8 的 UBT 要 .NET 10,用引擎自带的 dotnet,别装系统级
/e/UE_5.8/Engine/Binaries/ThirdParty/DotNet/10.0/win-x64/dotnet.exe \
  /e/UE_5.8/Engine/Binaries/DotNET/UnrealBuildTool/UnrealBuildTool.dll \
  -projectfiles -project="路径/工程.uproject" -game -rocket -progress   # 生成 sln
# 同一 dll 换参数:工程名Editor Win64 Development -project=... -waitmutex   # 编译
⚠️ 翻车实录 ×3:① Target.cs 抄旧教程用 BuildSettingsVersion.V5 → 报 "build products in common with UnrealEditor" 冲突,改 V7 解决(错题本 P8)。② 插件名凭印象写 GameplayStateTreeModule → "Unable to find plugin",真名 GameplayStateTree,以引擎 Plugins 目录里的 .uplugin 文件名为准(P9)。③ 直接运行 UnrealBuildTool.exe 报缺 .NET 10——用引擎自带 dotnet(P10)。
原理一句话:C++ 化只是给工程加装了一个"自定义模块"的挂载点,之后我们的两个类就挂在这里。对现有资产零影响,删 Source + 缓存即可退回纯蓝图。

第 2 步 · GAS 地基(C++ 部分)

目标:两个 C++ 类,搭起整个战斗系统的骨架。这是全项目唯一必须写 C++ 的地方。

心智模型(先建立,再写代码)

概念一句话
ASC(战斗大脑)挂在角色身上的总线:持有属性、技能、Buff
AttributeSet(属性表)定义 HP/体力等字段,全项目唯一必须 C++ 的部分
GE(规则)改属性的一条规则:伤害-50、体力-20。纯蓝图资产,策划主战场
GA(技能)按顺序打 GE 的流程(连击、翻滚),第 4 章才写
GameplayTag(贴纸)状态标记:无敌、眩晕、死亡。伤害管线查它做判断

操作

写两个类(完整代码与逐行讲解见"文档地图"的笔记 01/02):

  • UMyAttributeSet:Health/MaxHealth/Stamina/MaxStamina + 元属性 Damage;ATTRIBUTE_ACCESSORS 宏生成访问函数;PreAttributeChange 钳制数值;PostGameplayEffectExecute 里拆"伤害包裹"扣血
  • ABaseCharacter:挂 ASC + 属性表,实现 IAbilitySystemInterface,BeginPlay 时三步(建上下文 → 生成 Spec → 施加)给自己打初始化 GE
⚠️ 翻车实录:编译报 C2027: 使用了未定义类型 FGameplayEffectModCallbackData——它的完整定义在 GameplayEffectExtension.h,AttributeSet.h 里只有前向声明,补 #include 即可(错题本 P11)。这是典型的"真编译错误":有错误编号、有文件行号——要学会和 IDE 红波浪线(IntelliSense 假错误)区分,后者用"重新生成工程文件"解决(P1)。
原理一句话:伤害不直接扣血,而是 GE 先把数值写进"伤害通道"(Damage 元属性),结算回调里再读出、清零、扣血——所有伤害来源汇聚到同一个处理台,以后加无敌帧、防御减伤只改一处。

第 3 步 · 编辑器配置(全鼠标,约 15 分钟)

目标:三个根标签 + 一个初始化 GE + 一个角色蓝图。

3.1 GameplayTag 根(可不进编辑器)

直接写 Config/DefaultGameplayTags.ini:

[/Script/GameplayTags.GameplayTagsList]
GameplayTagList=(Tag="Ability",DevComment="")
GameplayTagList=(Tag="State",DevComment="")
GameplayTagList=(Tag="Event",DevComment="")

3.2 GE_InitAttributes

内容浏览器 → 添加 → 蓝图类 → 所有类搜 GameplayEffect → 创建命名 GE_InitAttributes。打开后 Duration Policy = Instant,修饰符(Modifiers)加 4 条:MaxHealth / Health / MaxStamina / Stamina,全部 Override 100。

3.3 BP_BaseCharacter

同样方式搜 BaseCharacter(我们的 C++ 类)创建蓝图。细节面板:Init Attributes Effect 填 GE_InitAttributes;Auto Possess Player = Player 0;Mesh 组件给个看得见的骨骼网格(引擎自带 SKM_Manny_Simple 即可)。

⚠️ 翻车实录(本教程最阴的坑):GE 的属性下拉里找不到自己写的 Health/Stamina,蓝图里也搜不到 C++ 类,日志零报错。三级倒查:属性失踪 → 游戏模块未加载 → .uproject 的 "Modules" 数组被编辑器覆写插件配置时清空成了 []。解法:补回模块注册并重启(完整过程见错题本 P14)。教训:编辑器能打开 ≠ 模块已加载;开关插件后留意 .uproject 的 git diff。

第 4 步 · 验收

  1. BP_BaseCharacter 拖进关卡,PIE 运行
  2. 按 ` 开控制台,输入 showdebug abilitysystem
  3. 屏幕左侧面板显示 Health: 100 Stamina: 100 → 通关 ✅

此刻你拥有的东西,比看上去多得多:伤害管线(GE → 通道 → 结算回调)已经闭环,UI 刷新靠属性变化通知天然支持,体力消耗/回血/Buff 都只是"再加一条 GE"的事。这就是选 GAS 而不是 ApplyDamage 的理由。

第 5 步 · 主角接入(输入 / 移动 / 动画 / 相机)

目标:第三人称主角能跑能跳,相机是魂系俯视构图。分工惯例从这步定型:重复管线进 C++,数值与表现留蓝图。

操作主线

  1. C++(管线):弹簧臂+相机组件、SetupPlayerInputComponent 绑定 Enhanced Input、Move/Look、自由移动模式(角色朝移动方向转身);默认俯角做成 UPROPERTY DefaultCameraPitch=-15,BeginPlay 写 ControlRotation
  2. 输入资产:IA_Move/Look/Jump + IMC(可脚本生成);WASD 修改器手动加:D 无 / A 取反 / W 拌和(YXZ)/ S 拌和+取反(bool 默认落 X 轴,原理见术语表)
  3. 动画:普通混合空间 BS_Jog(横轴 Speed 0~400,Idle/Jog_Fwd)+ 动画蓝图双状态(Ground/Air),Speed 与 IsInAir 由事件图表驱动
  4. 相机手感:臂长/延迟/碰撞在 CameraBoom 面板调
⚠️ 翻车实录 ×3:① 脚本给 IMC 写修改器"成功"但没生效——map_key 返回的是副本,修改器只能编辑器手加(错题本 P16);② 想给弹簧臂设"相对旋转 -15°"做默认俯角——开了 pawn 控制旋转后相对旋转被整体替换,纯摆设,正解是设控制器初始俯仰(P17);③ 用脚本搬 World Partition 地图连续失败——WP 地图搬家只能编辑器 GUI 拖拽(P15)。
架构心得:移动模式决定混合空间维度——自由移动(转身朝移动方向)只要 1D 速度轴;方向×速度的 2D 混合是锁定模式(第 7 章)的事。别提前建用不到的复杂度。

第 6 步 · 三连击与伤害(已完成)

目标:左键三段普攻,命中扣血,体力消耗,连击窗口。

2026-10-17 用户确认最新版本正常。三连击、体力消耗与玩家血条/体力条已完成。当前配置以 复工清单 及策划案为准。

设计一句话

输入统一发 Ability.Attack.Light;三个 GA(标签 .Light.1/2/3)利用标签父子匹配同时被尝试,GA2/3 靠 State.Combo.Window 门槛卡死窗口外激活;命中帧和窗口开启都是蒙太奇时间轴上可拖的通知(自定义 AN_SendGameplayEvent 发 GameplayEvent),伤害走第 2 章就位的元属性通道。

调试心法:GameplayEvent 链路故障全部静默丢失、零报错。WaitGameplayEvent 后先接 Print String 验证链路,再接正式逻辑。排查三问:通知放对帧了吗?标签两边拼写一致吗?事件发给对的 Actor 了吗?

详细构建步骤(GE_Damage/GE_ComboWindow/GA×3/木桩)见 docs/log/04-三连击与伤害.md。
