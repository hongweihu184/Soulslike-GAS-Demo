## 脚本主干

1. Goal.Activate 建立动作权重表、动作函数表及参数表，读取距离、事件请求、队伍角色、血量和 ThinkParam 变体。
2. 按 if/elseif 顺序处理特例，再根据距离填充普通行为权重。
3. 对 Act05 的权重调用 SetCoolTime，参数包含动作 3003、20、原权重、0。可确认它针对一个动作，而非给所有攻击施加统一冷却；此处不把参数 20 的单位当作已验证事实。
4. 注册各动作函数及 ActAfter_AdjustSpace，然后调用 Common_Battle_Activate。
5. 各动作向子 Goal 队列添加靠近、攻击、后退、侧移或转身。Goal.Update 调用默认子目标完成检查；Interrupt 对指定目标越界事件清空子目标。

## 普通正面交战时的权重

下表只适用于没有触发事件、特殊 ThinkParam、侧后方向或队伍角色优先分支的普通变体。远距两个区间（d≥10 与 5.5≤d<10）在普通变体下权重相同，所以合并。

| 原脚本距离 d | Act01 连击A | Act02 连击B | Act04 两段攻击 | Act05 动作3003 | Act06 动作3007 | Act12 侧移 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| d≥5.5 | 15 | 10 | 0 | 10 | 45 | 20 |
| 1.5≤d<5.5 | 20 | 20 | 15 | 35 | 0 | 10 |
| d<1.5 | 25 | 15 | 15 | 45 | 0 | 0 |

这些是**冷却处理之前的权重**，不是始终有效的最终百分比。Act05 权重被过滤后，剩余选项的相对概率会改变。

特殊分支还包括：事件请求→Act20；特殊 110054→靠近辅助调用；队伍角色→后退/侧移偏好；侧后方向条件→不同攻击及转身权重；特殊 144040/144041→Act20/21。第一版教学树应把这些作为单独的扩展分支，不把它们混成普通近战参数。

## 等价行为树草图

这是根据脚本推导的表达；其中“执行既有动作时保持 Running、只在决策点重新选择”是 UE 落地建议。具体引擎调度频率未在本轮确认。

```text
Combat（已经进入战斗；感知与脱战不在本文件证据内）
├─ 事件：指定目标范围中断
│  └─ 清空当前子目标，让后续决策重新建立行动
└─ 一个决策周期 Sequence
   ├─ 采样距离、方向、队伍角色、血量、ThinkParam、事件请求
   ├─ 构建候选动作（按脚本条件优先顺序）
   │  ├─ 事件/特殊变体分支
   │  ├─ 队伍角色分支
   │  ├─ 侧后方向分支
   │  └─ 普通距离权重表
   ├─ 冷却过滤：更新特定动作的权重
   ├─ 选择一次 Action（辅助函数显示为按权重抽取）
   ├─ 持续执行所选 Action
   │  ├─ Act01/02/04：靠近辅助 → 连击子目标序列
   │  ├─ Act05/06：靠近辅助 → 单个攻击子目标
   │  ├─ Act11：视条件先靠近 → 后退
   │  ├─ Act12：侧移
   │  └─ Act13：转身
   └─ 可选的攻击后调整 → 完成该周期
```

如果用 UE 原生节点实现，动态权重抽取不能直接等同于普通 Selector 的“从左到右选第一个成功项”。可用一个 SelectCombatAction Task 写入黑板 SelectedAction，然后由带枚举条件的 Selector 分派各动作 Sequence。动作进行中持续运行，完成或收到明确中断后才重新选择，避免 Service 每次刷新就重抽动作。

## 攻击序列如何拆

Act01：先调用 Approach_Act_Flex；随机数 1～100 小于等于 25 时添加 3000→3001 两段，否则添加 3000→3001→3002 三段。这里是排入子 Goal 的两种序列，不保证游戏内每一段都会无条件命中或执行到底。

Act02 同样是两段/三段序列，但起始动作换成 3001。Act04 是 3002→3001。Act05 是 3003。Act06 是 3007，其传给靠近辅助的距离参数比前几类攻击更远。

动作 3000、3001 等是原始 ID，本轮未查看动画，不将它们命名为横斩、突刺或冲锋。Approach_Act_Flex 的内部步行/奔跑选择、失败结束和实际朝向约束需要继续追踪。

**关键组织方式**：选择的是包含准备移动的完整行动。可在距离较远时选择攻击行动，然后由它负责靠近再出招；不必把所有行动先汇入唯一的“到达攻击圈”节点。

## 攻击后调整是独立的一步

Act01/02/04/05/06 均返回 GetWellSpace_Odds=50；Act11/12/13 返回 0。配合 Common_Battle_Activate 的辅助线索，可解释为攻击行动具有条件性的后续调整，而非每次动作结束都固定等待一段时间。实际概率调用链的完整正确性仍受公共辅助文件未整体验证的限制。

在本文件的 AfterAttackAct 中，忽略队伍角色特例后：

| 进入调整时的距离 d | 分支结果 |
| --- | --- |
| d≥6 | 25% 侧移，否则加入靠近至 5.5 的子目标 |
| 4≤d<6 | 30% 侧移，其余不添加移动子目标 |
| 2≤d<4 | 15% 侧移、10% 后退，其余不添加移动子目标 |
| 0.5≤d<2 | 5% 侧移、15% 后退，其余不添加移动子目标 |
| d<0.5 | 15% 后退，其余不添加移动子目标 |

侧移和后退的时长参数在 2.5～4.5 范围随机；普通后退目标为当前距离加一个 2.5～4.5 的随机量。未添加移动子目标**不等于显式 Wait，更不等于已经证明它会站定冷却若干秒**。

## 对本项目的建议（尚未实施、待体验验证）

保留现有 BT 主干及用户指定的 140→200、190→150 作为基础走位。先学习两个结构：

1. 将“攻击行动”表达为准备靠近→一次攻击/连段→结束，而不是仅在统一攻击圈内挑选攻击。
2. 将“攻击后调整”作为可选分支，能够选择后退、侧移、短暂停顿或直接结束；这些选项要受自身配置与中断规则约束。

不建议第一步照搬全部动作权重或多怪角色逻辑。最小验证是两种攻击行动加一种攻击后调整，观察：能否说明每次移动的目的；接近是否频繁重启；攻击是否被普通距离变化打断；动作结束是否每次停顿相同；玩家是否仍难判断有效攻击距离。此处是后续原型建议，没有声称已经得到手感支持。
