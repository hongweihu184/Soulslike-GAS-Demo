## 实测结果

| 样本范围 | 文件数 | 成功反编译并重新编译 | 严格比较匹配 |
| --- | ---: | ---: | ---: |
| m30_00_00_00 中全部敌人 battle.lua | 29 | 29 | 28 |
| 手动选择的 aicommon 通用行为文件 | 14 | 14 | 5 |
| 合计 | 43 | 43 | 33 |

43 个文件共含 933 个函数原型。33 个整文件匹配样本包含 629 个函数原型；未对剩余 304 个函数逐个计数匹配比例，不能说它们全部有错。

这里的严格比较由独立的 Lua 5.0 二进制解析器完成，包含文件头、参数数量、upvalue 数量、vararg 标记、最大栈、原始常量（字符串按原始字节比较）、子函数顺序与结构、全部指令。忽略源码名、行号、局部变量调试名/作用域、upvalue 调试名及封包尾部填充。它不是整个文件逐字节相同，也不包含引擎运行验证。

比较器自检：分别编译 return 1 与 return 2，能正确识别差异，避免上游比较器遗漏常量表的问题。测试记录在 `Saved/Research/DS3/validation/comparator-probe.json`。

全部 43 份输出没有反编译器自身警告；其中仍有 10 个不匹配，说明“无警告、能重新编译”不足以证明还原正确。共同函数含可见乱码，编码可能参与部分差异，但本轮没有完成所有差异归因，不应把它们全部归结为编码。

未匹配文件：m30_00_00_00/139000_battle.lua，以及 aicommon 的 approach_target、attack_tunable_spin、combo_attack_tunable_spin、common_battle_func、common_enemy_function、common_enemy、common_func、continue_keepdist、turn。研究这些输出时需要额外核对。

本轮是单一游戏安装、一个地图包与部分公共脚本的抽样结果，不能外推整个 DS3、HKS 或全部魂系作品的正确率。此前 32 个公开通用 Lua 样例的结果依然成立，两次测试的样本与比较标准不同。

## 建议从这两份已匹配文件开始

### 110000_battle.lua：剑盾敌人的行动组织

[打开反编译结果](E:/UE5.8Project/ProjectUnreal/Saved/Research/DS3/validation/m30_00_00_00/110000_battle.lua.dec.lua)

注册名称为 MoujaSoldier_SwordShield_110000_Battle，可以据此称作剑盾敌人脚本；本轮没有用角色资源或游戏内实体确认其中文名称及具体刷怪点。

| 阅读位置 | 已核对的脚本事实 |
| --- | --- |
| Goal.Activate | 读取距离、高度差、血量、事件请求、队伍角色等信息，设置动作权重表，再传入 Common_Battle_Activate |
| Act01 及其他攻击动作 | 先调用 Approach_Act_Flex，再把连击/终结攻击加入子 Goal；不同动作可以设置不同距离与后续安排 |
| Act06、Act09 | 部分攻击后加入 1.4～2.2 秒随机等待，并设置目标距离范围 |
| Act11 | 条件满足时调用靠近辅助函数，随后加入 LeaveTarget 子 Goal |
| Act12 | 加入持续 4 秒的 SidewayMove，方向和角度包含随机参数 |
| Act13 | 加入 Turn 子 Goal；这些参数不足以单独证明最大旋转速度的底层实现 |
| ActAfter_AdjustSpace 与后续 AfterAttackAct | 存在独立的攻击后调整行动组织 |

这份脚本证明其行为组织比“靠近→冷却完就打”的单一循环丰富。动作被作为子目标组织，决策涉及距离、动作历史、随机与队伍信息。不过 Goal 的调度、原生移动和动画底层并未在此还原，不能据此宣称整个引擎就是 UE 行为树、标准 HTN 或某个固定 FSM。

### after_attack_act.lua：攻击后动作选择

[打开反编译结果](E:/UE5.8Project/ProjectUnreal/Saved/Research/DS3/validation/aicommon/after_attack_act.lua.dec.lua)

整文件通过严格比较。可观察到：先检查距离和朝向，再读取不同选项的权重；候选包括无动作、后退接侧移、后退、后跳、侧跳、短暂停顿及组合。部分子目标附加距离/角度约束，并提供相应中断回调。

这支持一个对我们有用的设计方向：将“攻击后做什么”独立为可配置行为，不要求每次攻击结束都回到完全相同的站定动作。这是从脚本得到的设计推论，并不是本轮对 UE 项目的新修改。
