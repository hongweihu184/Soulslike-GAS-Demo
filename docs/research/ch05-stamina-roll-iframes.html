0. 这个系统是什么、为什么这样做

第 5 章要给主角加三样东西,它们共享同一个内核:把"资源"和"状态窗口"都交给 GAS 和动画时间轴管理。

  • 体力(Stamina):翻滚/攻击消耗资源,耗尽就不能再动作 → 用 GA 自带的 Cost Gameplay Effect 机制扣,用 Infinite + Period 的 GE 自动回。
  • 翻滚(Roll/Dodge):一个位移技能 → 用 GA + 蒙太奇 + (可选)Root Motion 位移。
  • 无敌帧(i-frame):翻滚中若干帧不吃伤害 → 不是一个"计时器",而是蒙太奇上的一个 ANS 窗口,窗口期间给角色挂 State.Invulnerable 标签,伤害结算处检查这个标签。
为什么延续"时间轴即状态机":本工程第 4 章已经确立架构——状态标签(State.MoveLocked、State.Combo.Window)的生灭由蒙太奇 ANS 通知管,GA 只管激活门槛和结算。无敌帧是同一类东西:它就是动画上的某一段帧区间。如果把无敌帧写成 GA 里的 0.4 秒 Delay,动画师一调蒙太奇时长,计时器和动画就对不上了(人还在空中翻滚,无敌已经没了)。把窗口挂在蒙太奇上,改动画时窗口自动跟着走。这也是商业魂类(Lords of the Fallen 开发者的 Quod Combat Framework)的做法,见 §3 引用。
三个系统的关系一句话:体力是"准入证"(Cost GE 决定你能不能滚),无敌帧是"翻滚时间轴上的一段标签窗口",取消衔接是"两段窗口标签相遇时谁取消谁"。三样东西全部是标签 + GE + ANS,新增 C++ 只有约 10 行。

1. 体力消耗与自动回复

1.1 官方与社区主流做法

做法机制评价
消耗:GA 的 CostGameplayEffectClass(官方机制) GA 类默认值里填一个 Instant GE(Modifier:Stamina −X)。CanActivateAbility 自动调 CheckCost 检查够不够,蓝图 GA 里调 Commit Ability 节点时 ApplyCost 真正扣掉。 ✔ 官方正道。体力不足时 TryActivateAbilitiesByTag 直接激活失败,不用自己写判断。tranek 文档 4.5.14 节讲的就是它。
回复:Infinite GE + Period 一个 DurationPolicy = Infinite 的 GE,填 Period(如 0.2s)和每周期 Modifier(Stamina +X),BeginPlay 时 ApplyGameplayEffectSpecToSelf 挂一次,常驻。 ✔ tranek 文档与 GAS Companion 的标配套路。回复速率改一个数字即可,天然支持预测与网络。
回复:Tick / Timer 手动加属性 角色 Tick 里 SetStamina(...) ✘ 绕过 GAS:不复制、不参与预测、不吃 GE 增减益,不要在 GAS 工程里这么干。
回复抑制(进阶):攻击/翻滚时不回体力 GE 上加 UTargetTagRequirementsGameplayEffectComponent,把 State.StaminaRegenBlocked 填进 Ongoing Tag Requirements 的 Blocked;动作期间由 ANS 挂该标签。 第 5 章可不做,列为可选。类魂里"翻滚后短暂延迟再回体力"用这套(抑制时再配 PeriodicInhibitionPolicy)。

2. 翻滚 GA 的设计:位移方案怎么选

2.1 三种方案对比(官方/社区观点)

方案机制手感网络代价结论
A. Root Motion 蒙太奇
(位移烘焙在动画里)		 动画序列开 Enable Root Motion,动画蓝图 Root Motion Mode = Root Motion from Montages Only;GA 里 PlayMontageAndWait,CMC 自动走位移。CMC 有专门的"网络蒙太奇根运动"路径(ACharacter::IsPlayingNetworkedRootMotionMontage,Character.h:1193 已验证)。 最好:位移与动画逐帧对齐,脚部不打滑 CMC 原生支持 调翻滚距离要回去改动画;素材必须带根位移 素材带 RM 就用它。类魂主机游戏主流。
B. AbilityTask_ApplyRootMotion*
(代码算位移)		 GA 里用 Apply Root Motion Constant Force 节点:任务构造一个 FRootMotionSource 交给 CMC,Duration 内按给定速度推胶囊体;蒙太奇播无根位移的动画纯做表现。 良好:匀速/曲线推位移,动画要挑"原地版" 走 CMC saved-moves 预测,任务参数自动复制(AbilityTask_ApplyRootMotion_Base.h) 动画与位移分离,需调 Strength/Duration 对齐动画节奏 素材不带 RM 时用它。Lords of the Fallen 开发者的冲刺/击退全用这套。
C. LaunchCharacter 给胶囊体一次性速度 飘:无时长控制,落地靠摩擦 不走预测,联网橡皮筋;单机也常被摩擦力吃掉距离 最低 不推荐,原型凑合可以,作品集不要用。
本工程选型:素材是 Paragon 系列。施工时先打开候选翻滚动画看底部时间轴有没有根骨骼(Root)位移曲线:有 → 方案 A;没有 → 方案 B(Apply Root Motion Constant Force + 原地翻滚动画)。待验证 Paragon 翻滚/闪避动画是否带 Root Motion(第 4 章施工时已复制过 Paragon 蒙太奇,届时直接看)。两条路的 GA 骨架完全相同,差别只在"位移谁驱动",先按方案 B 做最稳——距离/时长是 GA 上的两个数字,策划随时调。

3. 无敌帧(i-frame)的 GAS 实现

3.1 伤害闸门放在哪一层:三种放法对比

闸门位置做法评价
A. AttributeSet::PostGameplayEffectExecute
(本工程现状的 Damage→Health 结算处)		 结算 Damage 元属性前,查目标 ASC 有没有 State.Invulnerable,有则 SetDamage(0) 直接 return,不扣血。 ✔ 本工程最省:已有结算函数里加 4 行。tranek 文档的元属性结算范式就发生在这里,加标签闸门是同一位置的自然延伸。本工程选这个。
B. GE 的 TargetTagRequirements
(UTargetTagRequirementsGameplayEffectComponent)		 在 GE_Damage 上加组件,Application Tag Requirements 的 Blocked 填 State.Invulnerable → 整个伤害 GE 应用失败。 ✔ 最上游、最"配置化",不用改 C++;但 整个 GE 被吞掉,无法得知"这一刀被无敌帧躲了"(做不了完美闪避/提示音)。组件已在 5.8 源码验证存在(GameplayEffectComponents/TargetTagRequirementsGameplayEffectComponent.h,编辑器显示名 "Require Tags to Apply/Continue This Effect")。
C. PreGameplayEffectExecute 返回 false 属性集里 PreGameplayEffectExecute(AttributeSet.h:200 已验证)判断标签,返回 false 撤销本次 modifier。 可行但语义偏底层(撤销的是单个 modifier 应用),可读性不如 A;社区用得少。
商业实践佐证(Quod Combat Framework,Lords of the Fallen / Killsquad 开发者):"翻滚技能本身不含任何无敌逻辑"——无敌窗口是蒙太奇上的 Anim Notify State,窗口期间给角色挂一个 Infinite GE(只授予 Combat.State.Intangible 一个标签);伤害管线在扣血前查这个标签;被挡下的命中不丢弃,向目标 ASC 发一个 Event.Combat.HitNegated Gameplay Event,翻滚 GA 里 WaitGameplayEvent 监听它,若此时还在更窄的"完美闪避窗口"标签内,就升级成完美闪避奖励。标签只陈述"现在不能被命中",不说为什么——招架、过场、出生保护都可以授同一个标签,伤害代码一行不改。这套与本工程"时间轴即状态机"完全一致。

4. 翻滚取消攻击、攻击取消翻滚的衔接窗口

4.1 设计原理:取消 = "标签相遇规则",不是状态机 if-else

沿用"时间轴即状态机":能不能取消,由蒙太奇上的窗口标签生灭决定;GA 只声明标签规则。GAS 自带的两条规则(均在 GameplayAbility.h:739/743 已验证):

  • CancelAbilitiesWithTag:"我激活时,把身上带这些标签的激活中技能取消掉"。
  • BlockAbilitiesWithTag:"我存活期间,带这些标签的技能不许激活"。

类魂的规则映射:

衔接规则实现
翻滚取消攻击(任何攻击阶段都能滚) 翻滚几乎无门槛;激活时打断攻击 GA_Roll 的 Activation Blocked Tags 不含 State.Attacking(攻击中允许激活);CancelAbilitiesWithTag = Ability.Attack.Light(激活瞬间取消三连击 GA,蒙太奇被停 → 攻击蒙太奇上的 ANS End 触发 → State.Attacking / State.MoveLocked 自动摘除,这正是第 4 章已有机制的复用)。
攻击取消翻滚(只能取消翻滚后摇) 翻滚前半段(位移+无敌帧期)不许攻击;后段"取消窗口"开启后可以 不改攻击 GA 的门槛——攻击 GA 现在已被 State.MoveLocked 挡住(第 4 章现状)。做法:AM_Roll 上用 ANS 挂 State.MoveLocked,但只挂到"取消窗口开启帧"就摘掉(窗口帧 = 动画师在蒙太奇上拖的通知终点)。之后攻击自然能激活;再给三段攻击 GA 加 CancelAbilitiesWithTag = Ability.Roll,激活攻击时把还没播完的翻滚 GA 取消掉,位移源随之被任务 OnDestroy 移除,干净收尾。
翻滚取消翻滚(连滚) 同样只能在取消窗口后 GA_Roll 的 BlockAbilitiesWithTag 含 Ability.Roll 自带防连滚;窗口期后上一段 GA 已被 Cancel/End,自然解封。

6. 常见坑

  • P5-1 回复 GE 挂上瞬间先 + 一次:bExecutePeriodicEffectOnApplication 默认 true(GameplayEffect.cpp:187),回复 GE 要手动关掉,否则每次挂上白送一跳回复。
  • P5-2 Cost GE 必须 Instant:CheckCost → CanApplyAttributeModifiers 只按 Instant modifier 试算;填 Duration/Infinite GE 当 Cost 语义错误。同理 Cost GE 上不要挂标签授予组件当"消耗标记"用。
  • P5-3 体力不足时激活是"静默失败":TryActivateAbilitiesByTag 失败无任何表现,玩家会觉得"按键失灵"。第 5 章可先 UI 显示体力条兜底;"体力不足提示音/图标闪红"留给后续 GameplayCue 章节。
  • P5-4 蓝图 GA 忘调 Commit Ability 就不扣体力:Cost GE 只是"门槛+扣费定义",扣费动作在 K2_CommitAbility。Commit 要在 Play Montage 之前,且 Commit 返回 false 必须 EndAbility。
  • P5-5 PreAttributeChange 的 clamp 救不了 CheckCost:本工程 Stamina 已在 PreAttributeChange clamp 到 [0, MaxStamina],但 CanApplyAttributeModifiers 试算发生在 clamp 之前/之外——体力 10 时消耗 25,CheckCost 仍会判失败(这正是要的行为);不要试图靠 clamp 放行负数。
  • P5-6 取消路径不走 EndAbility,人会"幽灵滑行":ConstantForce 的位移源住在 CMC 里,只有任务的 OnDestroy 能移除。翻滚被眩晕/攻击取消时,必须保证 GA 的 Cancel 链走到 EndAbility/CancelAbility——用 CancelAbilitiesWithTag 自动取消的路径是安全的,手写"直接停蒙太奇"是危险的。
  • P5-7 结束速度模式选错,滚完漂移:MaintainLastRootMotionVelocity 会把 1500cm/s 的翻滚速度带进普通移动。翻滚用 ClampVelocity + 跑步速度上限。
  • P5-8 标签 ini 格式:5.8 只认 [/Script/GameplayTags.GameplayTagsSettings] 段的 +GameplayTagList=,老教程的 GameplayTagsList 段已失效(错题本 P23)。
  • P5-9 RemoveActiveGameplayEffectBySourceEffect 按栈移除:同一 GE 类如果可能同时存在两个窗口(未来多段翻滚),要改存 FActiveGameplayEffectHandle 按句柄摘;第 5 章单窗口不用管。
  • P5-10 动画与位移二选一驱动:蒙太奇开了 Root Motion 又叠 ConstantForce = 两套系统抢胶囊体,位移结果不可预期(Quod 原文警告)。方案 A/B 互斥。
