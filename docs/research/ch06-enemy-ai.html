① 这个系统是什么、为什么这样做

第 6 章要把 BP_Dummy(继承 BaseCharacter,已有 ASC + 属性集,会挨打不会动)进化成真正的敌人。整套系统分三层,各自只管一件事:

层负责用的引擎设施
决策层(大脑)我现在该干什么:巡逻 / 追玩家 / 攻击 / 发呆AAIController + BehaviorTree + Blackboard
感知层(五官)玩家在哪:看见没有、听见没有UAIPerceptionComponent(视觉/听觉)
执行层(手脚)攻击动作、受击、死亡——一切"战斗行为"GAS:GA / GE / GameplayTag(和主角完全同一套)

为什么这么分工——这正是本项目第 4 章立下的架构原则的延伸:时间轴即状态机,状态标签生灭由蒙太奇通知管,GA 只管激活门槛和结算。敌人不需要输入系统,所以"按攻击键 → TryActivateAbilitiesByTag"这一步换成"行为树的 Task 节点 → TryActivateAbilitiesByTag"。GA 内部图完全不改,玩家和敌人共用同一套 GA_Attack 的写法范式;伤害结算(GE_Damage → Damage 元属性 → PostGameplayEffectExecute 扣血)一条链路双向复用:玩家砍敌人、敌人砍玩家,走的是同一份代码。

一句话结论:AI 的"智能"放在 BehaviorTree 里,AI 的"战斗力"全部走 GAS。BT 节点只负责"在合适的时机按下技能的开关",技能内部逻辑(蒙太奇、ANS 通知、伤害)敌人与主角共享。

ASC 放 Pawn 还是 AIController?

放 Pawn(Character) 上。理由:

  • 敌人死了就销毁/刷新,不需要跨重生保留属性和 GE,ASC 没必要放到更长寿的宿主上(PlayerState 方案是给"需要重生且保留属性"的玩家英雄用的)。
  • tranek 的 GASDocumentation 明确写:"不需要重生的东西(比如 AI 敌人、建筑、场景道具)让 Owner 和 Avatar 是同一个 Actor"——即 ASC 挂在 Pawn 上,OwnerActor == AvatarActor == Pawn。
  • 我们 BaseCharacter 构造函数里已经 CreateDefaultSubobject<UAbilitySystemComponent>,BP_Dummy 继承后天然自带,什么都不用挪。

② 官方与社区主流做法对比

2.1 ASC 归属与初始化(OwnerActor / AvatarActor)

做法来源结论
AI 敌人:ASC 挂 Pawn,InitAbilityActorInfo(this, this),Owner=Avatar=Pawntranek/GASDocumentation §4.1.2(样例工程 GDCharacterBase / APACharacterBase 即此写法)✅ 我们采用,且 BaseCharacter 已经就是这套
玩家英雄:ASC 挂 PlayerState(重生保属性),敌人挂 Pawn;多人时敌人 ASC 用 Minimal 复制模式同上,§4.1.5 + Fortnite 实践引用本项目单机 Demo,用不到,知道即可
ASC 挂 AIController零星老帖子❌ 非主流。Controller 换绑/重生时 ASC 生命周期尴尬,Epic 注释里 AvatarActor 定义就是"世界里的物理实体(Pawn/炮塔)"
源码意外收获:UE 5.8 的 UAbilitySystemComponent::InitializeComponent() 会自动调用 InitAbilityActorInfo(GetOwner(), GetOwner())(默认初始化为组件的外层 Owner)。ASC 作为 Character 的默认子对象时,Owner 就是 Character 自己——这就是本项目从没显式调用过 InitAbilityActorInfo、三连击却照常工作的原因(已验证:整个 Source/ProjectUnreal 无此调用,且该函数不是 UFUNCTION,蓝图里根本调不到)。单机 Demo 可以不补;但养成习惯,施工时顺手在 BaseCharacter::BeginPlay 里显式写一行 AbilitySystemComponent->InitAbilityActorInfo(this, this);,幂等无害,语义清晰。

2.2 BehaviorTree 驱动 GAS:三种范式

范式做法代表评价
A. 自定义 BTT 按标签激活(主流)写一个 BTTask_BlueprintBase 子类,ReceiveExecuteAI 里拿到 Controlled Pawn 的 ASC,调 TryActivateAbilitiesByTag,然后 FinishExecuteGAS Companion 插件直接内置 BTTask_TriggerAbilityByClass / BTTask_TriggerAbilityByTags(官方文档);大量教程(Udemy 高级 Action RPG 课程、各 YouTube 系列)同款✅ 我们采用。和主角"按键 → TryActivateAbilitiesByTag(父标签选拔)"的范式完全一致,GA 不用改
B. BT 发 GameplayEvent,GA 的 AbilityTriggers 被动响应BTT 里调 SendGameplayEventToActor,GA 配置 AbilityTriggers = (Event.Xxx, On Gameplay Event)受击/死亡这类"被动反应"的标准做法(tranek 样例的受击动画就是这么挂的)✅ 用于受击/死亡(见 §4 第 8、9 步);主动攻击用 A 更直观
C. GA 自己驱动行为(GA 里写移动/寻路)GA 里用 AbilityTask 移动角色Motion Warping 流、部分 ARPG 教程的"冲刺攻击"⚠️ 与 BT 的 MoveTo 抢移动控制权,决策链分裂。本项目不用;以后做"锁定目标冲砍"可考虑 Motion Warping 辅助位移,另开研究
社区共识:BT 管"什么时候打、往哪走",GA 管"怎么打、打多少血"。行为树里还可以直接用引擎自带的 BTDecorator_CheckGameplayTagsOnActor 装饰器读 ASC 上的标签(比如 State.Dead)当分支条件——BT 和 GAS 的官方桥梁,已验证存在。

2.3 感知:AIPerception vs PawnSensing

无脑选 AIPerception:多感官合一(视觉/听觉/伤害/触碰)、带刺激源注册与衰减、带 GameplayDebugger 可视化。PawnSensingComponent 是老系统,功能子集,新项目不推荐。官方与社区教程(Epic Developer Community、各 UE5 敌人 AI 系列)全部以 AIPerception 为准。

2.4 受击与死亡的触发点

tranek 样例工程明确在 PostGameplayEffectExecute 里"扣血之后"做受击动画、跳伤害数字、给凶手发经验——和我们的 MyAttributeSet 结构一模一样,钩子就挂在 Damage→Health 结算之后。死亡用标签 State.Dead 标记,靠 GA(Activation Owned Tags)或装饰器查询。这也是 GAS 官方社区教程里"Event 驱动被动技能"的标准用法。

④ 本工程落地方案(回来施工时照此顺序做)

标记说明:资产/配置蓝图C++。除第 1、8、9 步外全程编辑器内完成,不用写代码。

资产/配置第 1 步:加标签(DefaultGameplayTags.ini)

用 5.8 格式 +GameplayTagList=(错题本 P23:老教程的 GameplayTagsList 段格式已失效),追加到 Config/DefaultGameplayTags.ini:

+GameplayTagList=(Tag="Event.Damaged",DevComment="受到伤害事件(伤害结算后由属性集发出)")
+GameplayTagList=(Tag="Event.Death",DevComment="死亡事件(HP 归零时由属性集发出)")
+GameplayTagList=(Tag="State.Dead",DevComment="死亡状态(GA_Death 激活期间持有)")
+GameplayTagList=(Tag="State.HitReact",DevComment="受击硬直中")
+GameplayTagList=(Tag="Ability.Attack.Enemy",DevComment="敌人普攻(父标签选拔用)")
也可以在编辑器 Project Settings → GameplayTags 里加,效果相同,别两处混着加重复行。

C++第 2 步(可合并进第 8/9 步一起做):BaseCharacter 补一行显式初始化

BaseCharacter.cpp 的 BeginPlay() 开头(Super 之后)加:

AbilitySystemComponent->InitAbilityActorInfo(this, this);

不改也能跑(引擎默认初始化,见 §3.1),加上是为了语义明确、以后上 PlayerState 架构时不踩坑。

蓝图第 3 步:BP_Dummy 基础设置

  1. 打开 Content/Gameplay/Characters/BP_Dummy,Details 面板搜 "AI":
    • AI Controller Class = 第 4 步要建的 BP_EnemyAIController
    • Auto Possess AI = Placed in World or Spawned(否则控制器不附身,BT 永远不跑)
  2. Class Defaults 的 Startup Abilities 数组填入三个 GA:GA_EnemyAttack(第 6 步建)、GA_HitReact(第 8 步)、GA_Death(第 9 步)。不授予就不会被事件/标签激活,这是最容易漏的一步。
  3. Event BeginPlay:调 RegisterWeaponCollision(蓝图里取武器上的碰撞盒组件传入)——和第 4 章给主角做的完全一样,敌人伤害链路直接复用。
  4. 确认 InitAttributesEffect 已填(GE_InitAttributes),让敌人血量初始化。

蓝图第 4 步:建 BP_EnemyAIController + 感知

  1. 内容浏览器右键 → Blueprint Class → 搜 AIController 为父类,命名 BP_EnemyAIController。
  2. 组件面板 → Add Component → AIPerception(必须手动加,AAIController 默认没有,§3.2 已验证)。
  3. 选中 AIPerception 组件,Details → Senses Config 数组加两项:
    • AI Sight config:Sight Radius = 1500,Lose Sight Radius = 1800(必须 ≥ Sight Radius),Peripheral Vision Half Angle = 70,Detection by Affiliation 三项全勾(Detect Enemies / Neutrals / Friendlies——没配队伍系统时玩家算 Neutral,只勾 Enemies 会看不见玩家!)
    • AI Hearing config(可选):Hearing Range = 1200,三项全勾。要真正产生听觉刺激,攻击/跑动处需要发噪声(BTTask_MakeNoise 或 Pawn 的 Make Noise 节点);第 6 章可以先不配,留到做"背后偷袭被发现"手感时再加
  4. 事件图:
    • Event OnPossess → Run Behavior Tree(BTAsset = 第 7 步建的 BT_Dummy)。不要用 BeginPlay——控制器 BeginPlay 时可能还没附身
    • AIPerception 组件拖进图里 → 绑 On Target Perception Updated(Actor, Stimulus):
      • Stimulus → Was Successfully Sensed 分支
      • True:Get Blackboard → Set Value as Object(Key = TargetActor,Value = Actor);Set Value as Bool(Key = HasLineOfSight,true)
      • False:Set Value as Bool(HasLineOfSight,false);Set Value as Vector(LastKnownLocation,Stimulus.Stimulus Location);(可选)Delay 3s 后 Clear Value(TargetActor)——丢失目标后原地戒备而不是永远死追

蓝图第 5 步:建黑板 BB_Dummy

右键 → Artificial Intelligence → Blackboard,命名 BB_Dummy,加三个 Key:

Key 名类型说明
TargetActorObject(Base Class = Actor)当前仇恨目标
HasLineOfSightBool此刻是否看得见
LastKnownLocationVector最后看见的位置(丢失后去查看)

蓝图第 6 步:敌人攻击 GA 与自定义激活任务

6a. GA_EnemyAttack

  • 复制一个 GA_Attack_Light_1 改名 GA_EnemyAttack,换敌人的攻击蒙太奇(蒙太奇必须来自敌人自己骨架的动画,Paragon 各角色骨架不通用)。
  • Ability Tags 改为 Ability.Attack.Enemy(第 1 步加的)。
  • 图内部不动:Play Montage and Wait + ANS 通知(伤害帧开武器碰撞、State.MoveLocked 生灭)全部照旧——架构原则不变:GA 只管激活门槛和结算。

6b. BTT_ActivateGameplayAbility(自定义任务)

  1. 右键 → Blueprint Class → 父类搜 BTTask_BlueprintBase,命名 BTT_ActivateGameplayAbility。
  2. 加变量 AbilityTags,类型 Gameplay Tag Container,开 Instance Editable(小眼睛)。
  3. 重载 Event Receive Execute AI(节点签名:Owner Controller, Controlled Pawn): 
    Controlled Pawn
  → Get Ability System Component(蓝图纯函数,库函数,先走接口再找组件)
  → Try Activate Abilities by Tag(Tags = AbilityTags)→ 返回值 False 时打日志
  → Finish Execute(Success = true)
  4. 简化策略:不等技能结束,立即 Finish Execute,后接一个引擎自带 Wait 任务(1~1.5s)充当攻击间隔。等技能结束再返回需要绑 ASC 的 OnAbilityEnded 委托,蓝图侧可行性待验证,不做。

蓝图第 7 步:行为树 BT_Dummy

右键 → Artificial Intelligence → Behavior Tree,命名 BT_Dummy,Blackboard Asset 选 BB_Dummy。结构:

Root
└─ Selector
   ├─ Sequence [装饰器1:Blackboard(HasLineOfSight == true)]      ← 战斗分支
   │   ├─ Rotate to Face BB Entry(TargetActor)
   │   ├─ Move To(TargetActor,Acceptance Radius ≈ 150)
   │   ├─ BTT_ActivateGameplayAbility(AbilityTags = Ability.Attack.Enemy)
   │   └─ Wait(1.0 ~ 1.5s,随机偏差 0.3)
   ├─ Sequence [装饰器2:Blackboard(TargetActor 已设置 且 HasLineOfSight == false)]  ← 追丢分支(可选)
   │   └─ Move To(LastKnownLocation)
   └─ Wait(2s)                                                    ← 待机/巡逻占位
  • 两个 Blackboard 装饰器的 Observer Aborts 都设为 Self 或 Both——否则黑板变了树不会即时换分支(社区高频坑)。
  • 装饰器条件勾 "Is Set" 判 TargetActor 是否有效。
  • Selector 从上到下优先级递减;战斗中 HasLineOfSight 变 false 时装饰器 1 会 Self-abort 打断攻击链,自动落入分支二。
  • 地图里必须有 Nav Mesh Bounds Volume(体积包住战斗区域),按 P 显示绿色可行走区域;没有 NavMesh,Move To 立即失败。

C++第 8 步:受击钩子(MyAttributeSet 里发 Event.Damaged)

MyAttributeSet.cpp 顶部加 include:

#include "AbilitySystemBlueprintLibrary.h"
#include "GameplayTagContainer.h"

PostGameplayEffectExecute 的 Damage 分支,在 SetHealth(...) 之后追加:

// 受击事件:通知 GA_HitReact
AActor* Owner = const_cast<AActor*>(OwnerActor); // OwnerActor 即上面已有的 GetOwningActor()
if (Owner)
{
    FGameplayEventData Payload;
    Payload.Instigator = Data.EffectSpec.GetContext().GetInstigator();
    Payload.Target = Owner;
    UAbilitySystemBlueprintLibrary::SendGameplayEventToActor(
        Owner, FGameplayTag::RequestGameplayTag(FName("Event.Damaged")), Payload);

    // 死亡事件(第 9 步用)
    if (GetHealth() <= 0.f)
    {
        UAbilitySystemBlueprintLibrary::SendGameplayEventToActor(
            Owner, FGameplayTag::RequestGameplayTag(FName("Event.Death")), Payload);
    }
}
注意:这个钩子在属性集里,玩家和敌人共用——玩家被打也会触发 GA_HitReact(只要你给玩家也授予了它)。不想要玩家受击硬直的话,第 3 步只给 BP_Dummy 授予 GA_HitReact 即可,代码不用加 if。

GA_HitReact(蓝图)

  • 新建 GA,父类 GameplayAbility,命名 GA_HitReact。
  • Class Defaults → Ability Triggers 数组加一条:Trigger Tag = Event.Damaged,Trigger Source = On Gameplay Event(§3.1 已验证枚举存在)。授予后 ASC 自动挂监听,事件到达即激活,图里不用 Wait 节点。
  • 图:Event Activate Ability → Cancel Abilities(With Tags = Ability.Attack,打断敌人自己正在放的攻击)→ Play Montage and Wait(受击蒙太奇)→ End Ability。
  • Activation Owned Tags 可加 State.HitReact;蒙太奇里的 ANS 通知照旧发 State.MoveLocked,与第 4 章架构一致。

蓝图第 9 步:死亡 GA_Death

  • 新建 GA_Death,Ability Triggers 加 Event.Death(On Gameplay Event)。
  • Activation Owned Tags = State.Dead(技能激活期间挂在 ASC 上,BT/其他 GA 都能查)。不要在 End Ability 里移除——把 bResurrectOnEnd 之类都别想,GA_Death 激活后不主动 End Ability,标签就一直挂着。
  • 图(Event Activate Ability 起):
    1. Cancel All Abilities(清掉正在进行的攻击/受击)
    2. Get Character Movement → Disable Movement(停止移动与寻路)
    3. Get Controller → Get Brain Component → Stop Logic(Reason = "Dead")——行为树停跑,比 StopTree 更顺手;不调用的话靠下一步碰撞关闭也能保证不再打人,但树会继续空转耗性能
    4. Get Capsule Component → Set Collision Enabled(No Collision)(或 Set Collision Response to Channel: Pawn = Ignore,保留地面碰撞)
    5. Play Montage and Wait(死亡蒙太奇)→ On Completed → Set Life Span(如 5.0,尸体停留 5 秒后自动销毁)
  • 布娃娃替代方案(想要被砍飞的物理感):第 5 步换成 Mesh → Set Collision Profile Name("Ragdoll")→ Set Simulate Physics(true);记得先把胶囊体碰撞关掉,否则胶囊体继续挡路。二选一,Demo 推荐先用死亡蒙太奇(定格在最后一帧的效果 = 蒙太奇勾 bEnableAutoBlendOut = false 或不 End Ability)。
  • 行为树侧双保险:Root 下战斗 Sequence 再加一个引擎自带装饰器 Check Gameplay Tags on Actor(BTDecorator_CheckGameplayTagsOnActor,§3.2 已验证):Actor To Check = Self,Gameplay Tags = State.Dead,勾 Invert(即"没有 State.Dead 才执行")。

施工自检清单(每步做完打勾)

  1. 标签进 ini,编辑器 GameplayTags 面板能搜到 5 个新标签
  2. PIE 里敌人 ASC 上有 StartupAbilities(ShowDebug AbilitySystem 可查)
  3. 敌人面前走过 → 黑板 TargetActor 被写入(行为树编辑器连 PIE 实例实时看)
  4. 敌人追上来出招,玩家掉血;玩家砍敌人,敌人掉血 + 播受击
  5. 敌人 HP 归零 → 死亡蒙太奇 → 不再移动不再攻击 → 5s 后消失

⑤ 常见坑(按踩坑概率排序)

  1. AI 完全不动:99% 是 Auto Possess AI 没设(默认 Not Placed in World or Spawned 的反面)或没调 Run Behavior Tree。先查这两个。
  2. 感知组件没反应:AAIController 不自带 AIPerception 组件(源码已验证),必须手动 Add Component。
  3. 看得见别人就是看不见玩家:Detection by Affiliation 没勾 Neutrals。没配队伍系统(GenericTeamId)时所有 Actor 互为 Neutral(源码已验证默认三勾全 false)。
  4. On Target Perception Updated 丢了目标也触发:必须判 Stimulus.WasSuccessfullySensed(),否则"丢失"会被当成"看见"再写一次黑板。
  5. GA 不激活:没填 StartupAbilities(GiveAbility 是激活前提);或 Ability Tags 没写对;或 ini 标签格式用了废弃的 GameplayTagsList 段(P23)。
  6. Move To 瞬间失败:地图没有 Nav Mesh Bounds Volume,或目标点不在 NavMesh 上。按 P 检查。
  7. 黑板变了分支不换:装饰器 Observer Aborts 还是 None,改成 Self / Both。
  8. 蒙太奇播放失败/角色 T-Pose:攻击/受击/死亡蒙太奇是从别的 Paragon 角色拷来的,骨架不匹配。敌人用哪个角色资产包就用哪个包的动画。
  9. 死后还在挨打/出招:GA_Death 里忘了 Cancel All Abilities + Disable Movement + 关胶囊体碰撞,三件事都要做。
  10. 受击事件把玩家也打出硬直:钩子在 MyAttributeSet,全员生效;不给玩家授予 GA_HitReact 就等于玩家侧不响应,事件发了没人接,无害。
  11. Lose Sight Radius 比 Sight Radius 小:引擎要求 LoseSightRadius ≥ SightRadius,配反了感知会抖动。
  12. 听觉永远不触发:听觉是被动接收噪声事件,不像视觉主动扫描。得有人发噪声(Make Noise 节点 / BTTask_MakeNoise / StimuliSource 注册)。
