① 这个系统是什么、为什么这样做

本章要做四样东西:玩家 HUD 上的血条/体力条、敌人头顶血条、Boss 血条、伤害飘字。它们的共同数据源都是 UMyAttributeSet 里的 Health / MaxHealth / Stamina / MaxStamina / Damage。

核心问题是:UMG 控件(ProgressBar)怎么知道属性变了?有三条路:

  • Tick 轮询:每帧 GetFloatAttribute 再 Set Percent。能跑,但每帧都走蓝图虚拟机 + 字符串/结构体开销,官方和 tranek 的 GASDocumentation 都明确不推荐。入门教程爱这么写,是错题本级别的反模式。
  • 进度条的 Bind 绑定:右键 ProgressBar → Create Binding。看着优雅,本质也是每帧调用绑定函数取数,和 Tick 轮询同罪,只是藏得深。
  • 事件驱动(本章采用):ASC 内部维护一张「属性 → 委托」映射表,属性真正变化时才广播。控件只在广播回调里 Set Percent。属性没变,UI 一行代码不执行。这是 GAS 设计里给 UI 留的官方接口。
对应到本项目架构原则:和第 4 章「时间轴即状态机」一样,这里也是「数据流即 UI」——状态变化的源头(GAS 结算)直接推动 UI,中间不要有每帧巡逻的第三者。

MVVM 插件在 5.8 的现状(已在本机引擎目录核实)

  • 插件本体存在:E:\UE_5.8\Engine\Plugins\Runtime\ModelViewViewModel\ModelViewViewModel.uplugin,FriendlyName = "UMG Viewmodel"。
  • EnabledByDefault: false —— 没有内置默认启用,要在插件窗口手动开。
  • IsBetaVersion: true —— 5.8 里官方仍标 Beta。官方文档页也按 Beta 特性对待。
  • 关键类已存在:MVVMViewModelBase.h(UMVVMViewModelBase)、MVVMGameSubsystem.h、MVVMBlueprintView.h(路径见③)。
结论:简单项目不值得用。本章只有 4 个属性 2~3 个控件,事件委托两行就接完了;MVVM 的收益(FieldNotify 解耦、可测试性)要在设置菜单、背包这种几十个字段的界面才显现。Beta 状态 + 额外学习成本,对本项目(策划单人施工)是负收益。等做设置/背包界面时再回头评估。

④ 本工程落地方案(回来施工时照做)

对接现状:ABaseCharacter 上 AbilitySystemComponent 是 BlueprintReadOnly(蓝图可直接读),UMyAttributeSet 五个属性都通过 ATTRIBUTE_ACCESSORS 生成了 GetHealthAttribute() 等静态函数。本章不需要新增任何 GameplayTag,UI 纯数据驱动,与标签系统无关。

第 0 步(可选,C++ 两行,只为伤害飘字更干净)

在 MyAttributeSet.h 加一个广播结算伤害的动态委托,在 PostGameplayEffectExecute 里 Damage→Health 结算处广播。这样飘字不依赖「Damage 元属性变化→又被清零」的副作用,语义最干净。不写这步也能用蓝图方案(第 5 步备选)凑合。

// MyAttributeSet.h 类声明内加:
DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams(FOnDamageApplied, float, DamageAmount, AActor*, SourceActor);
// 类里 public:
UPROPERTY(BlueprintAssignable, Category = "Attributes|Meta")
FOnDamageApplied OnDamageApplied;

// MyAttributeSet.cpp PostGameplayEffectExecute 里 Damage 结算完成、SetHealth 之后加:
OnDamageApplied.Broadcast(LocalDamage, /*来源*/nullptr);

第 1 步:WBP_StatusBar(通用状态条控件)

  • 新建 WBP_StatusBar,画布放 ProgressBar(命名 Bar,勾 Is Variable)+ 可选 TextBlock 显示数值。
  • 加两个变量:TargetActor(Actor,Object Reference,Instance Editable + Expose on Spawn)、WatchedAttribute / WatchedMaxAttribute(类型 Gameplay Attribute,同样 Expose on Spawn)。
  • Event Construct:
    1. 初始化:Get Float Attribute(Target=TargetActor,Attribute=WatchedAttribute)和 WatchedMaxAttribute 各取一次 → Bar → Set Percent(Percent = 当前 / 最大)。
    2. 绑变化:异步节点 Wait For Attribute Changed(Target Actor=TargetActor,Attribute=WatchedAttribute,Only Trigger Once=false)→ 从 Changed 事件拉自定义事件 → 事件里重新 Set Percent。
    3. 若要在控件里同时监听 Max(上限变化场景),再放一个同样节点监听 WatchedMaxAttribute。魂类 Demo 上限不变,可只存一次初值。
  • Percent 计算需要缓存 Max 值:加一个 float 变量 CachedMax,初始化时填入,Changed 回调里 NewValue / CachedMax。

第 2 步:WBP_HUD(玩家 HUD)

  • 新建 WBP_HUD,左下角放两个 WBP_StatusBar 实例:HealthBar、StaminaBar(血条红色长条、体力绿色短条,魂类布局)。
  • WBP_HUD 的 Event Construct:
    1. Get Owning Player Pawn → 直接作为两个条的 TargetActor(条是实例,用「Expose on Spawn」变量在 Construct 后由父控件赋值:选中条实例 → 细节面板填 TargetActor = 绑定到变量)。
    2. HealthBar.WatchedAttribute 选 MyAttributeSet.Health,WatchedMaxAttribute 选 MyAttributeSet.MaxHealth;体力条同理 Stamina / MaxStamina。属性下拉框来自属性集的 UPROPERTY,直接搜得到。
  • 创建时机:在玩家 BP(BP_ThirdPersonCharacter 或其等价物)Event BeginPlay → Create Widget(Class=WBP_HUD,Owning Player=Get Player Controller 0)→ Add to Viewport。

第 3 步:敌人头顶血条(BP_Dummy 挂 WidgetComponent)

  • BP_Dummy 添加组件 Widget(WidgetComponent),命名 HealthBarWidget,挂到 Mesh 下或根组件,Location 抬到头顶(Z≈110,按 Paragon 体型微调)。
  • 细节面板:Space = Screen(屏幕空间,远处不缩小、不被遮挡,魂类头顶条标准做法)、Widget Class = WBP_StatusBar、Draw Size =(120, 12) 左右。
  • BP_Dummy Event BeginPlay:HealthBarWidget → Get User Widget Object → Cast to WBP_StatusBar → 设置 TargetActor = self、属性选 Health / MaxHealth,再调用一次初始化(如果控件的 Construct 早于赋值,把初始化逻辑收进控件的一个公开函数 Init(TargetActor, Attr, MaxAttr),这里手动调一次)。建议直接做成 Init 函数,HUD 那边也复用,避免 Construct 时序坑(见⑤)。
  • 显示策略(魂类):平时隐藏,受击后显示 4 秒再隐藏。BP_Dummy 里用同一个 Wait For Attribute Changed(Attribute=Health,OnlyTriggerOnce=false)→ Changed → HealthBarWidget → Set Visibility(Visible) → Set Timer by Event(4s)→ 隐藏。

第 4 步:Boss 血条模式

  • 不做 WidgetComponent。WBP_HUD 底部放第三个 WBP_StatusBar 实例 BossBar(更宽、带名字 TextBlock),默认 Visibility = Collapsed。
  • WBP_HUD 加公开函数 ShowBossBar(AActor Boss):给 BossBar 调 Init(Boss, Health, MaxHealth) → Set Visibility(Visible);再配 HideBossBar()。
  • 触发时机:锁定到 Boss / 进入 Boss 房触发盒时由关卡蓝图或 Boss 自身 BeginPlay 调 ShowBossBar(拿 HUD:Get Player Controller → Get HUD Widget 存引用,或第 2 步创建 HUD 时把它存进 GameInstance/PC 变量方便全局取)。本章若没有锁定系统,先用触发盒手动演示,锁定联动留到对应章节。

第 5 步:伤害飘字(WBP_DamageNumber)

  • 新建 WBP_DamageNumber:Canvas 里一个 TextBlock,做一段动画(上浮 40px + 淡出,1 秒),Animation 命名 FloatUp。
  • 控件加函数 Popup(float Amount, FVector2D ScreenPos):设文本 = Round(Amount)→ Set Position in Viewport(ScreenPos)→ Play Animation(FloatUp) → 动画结束 Remove from Parent。
  • 方案 A(写了第 0 步):BP_Dummy(或 BaseCharacter 蓝图子类)Event BeginPlay → 取自己的 ASC → … 实际最省事是:谁能拿到 AttributeSet 谁绑。蓝图里 Get Ability System Component → Get Attribute Set 类节点取不到 UMyAttributeSet 的自定义委托时,把绑定放在 WBP_HUD:监听所有敌人的飘字需要一个「受击者注册表」——简单做法:BP_Dummy BeginPlay 里 Create Widget(WBP_DamageNumber) 不 Add,先存着;Damage 委托回调里 Add to Viewport → Get Owner Actor → Get Actor Location(+Z 偏移)→ Project World Location to Screen(Player Controller 0)→ Popup。待验证:蓝图直接 Cast AttributeSet 到 MyAttributeSet 的节点路径,施工时先试 GetAbilitySystemComponent → GetAttributeSet(待验证节点名),不行就在第 0 步 C++ 里把委托挂到 BaseCharacter 上广播。
  • 方案 B(纯蓝图,不写 C++):BP_Dummy 里放 Wait For Attribute Changed(Attribute=MyAttributeSet.Damage,OnlyTriggerOnce=false)→ Changed → Branch:New Value > 0(过滤结算后清零的那次广播)→ 后续同方案 A 的投影 + Popup。原理:GE_Damage 先把 Damage 设成 50(触发一次,NewValue=50),PostGameplayEffectExecute 结算后清零(再触发一次,NewValue=0),过滤 0 即可。
  • 飘字每次投影一次即可(1 秒动画内位置不动),不用每帧跟随;要跟随就在控件里加极少量 Tick 或 Timeline 更新位置——飘字是允许 Tick 的例外,因为它活 1 秒就死。

⑤ 常见坑

1. 蓝图里搜不到 GetGameplayAttributeValueChangeDelegate。它不是 UFUNCTION(③已验证)。蓝图路线是异步节点 Wait For Attribute Changed;要原生委托就得写 C++。凭记忆在蓝图里硬找这个函数名是本类任务的经典错题。
2. 委托只在「变化时」触发,不会发初始值。控件 Construct 时必须先用 Get Float Attribute 读一次初值填条,否则进游戏血条是空的/满的直到第一次掉血。
3. Percent 要除以 Max,Max 变了条就错。每次回调用「NewValue / CachedMax」;如果以后有加血上限的装备/Buff,Max 属性也要再挂一个 Wait For Attribute Changed。
4. Damage 元属性会触发两次委托(设值 50 一次、结算清零一次)。方案 B 飘字必须过滤 NewValue > 0。这是 tranek 样例里同样存在的模式,不是 bug。
5. WidgetComponent 的 Space 选错。敌人头顶条用 Screen;World 模式会渲染到 RenderTarget 再贴网格,每个敌人一份 RT,敌人一多就是性能税,还会被场景遮挡。World 模式只在「要 UI 真实存在于世界里可被遮挡」时用。
6. GetUserWidgetObject 的时序。WidgetComponent 的控件在组件初始化后才创建;BP_Dummy BeginPlay 里立刻拿一般没问题,但控件自身 Construct 早于你赋 TargetActor,所以第 3 步强调用公开的 Init 函数手动初始化,不要依赖控件 Construct 时变量已就位。
7. HUD 拿 Pawn 的时机。WBP_HUD 的 Construct 里 Get Owning Player Pawn 可能为 null(控制器还没 Possess)。本项目 ASC 就在 Character 上且 BeginPlay 创建 HUD,一般安全;若遇到 null,把初始化延后一拍(Delay 0 或 Bind 到 OnPossessed)。
8. 联机注意(本项目单机可跳过):FOnAttributeChangeData.GEModData 只在服务器有值(tranek 注明);属性委托本身依赖复制,单机无影响。
9. MVVM 别手痒。5.8 里是 Beta 且默认关闭。本章控件只有 2~3 个,引入 MVVM 纯属加复杂度。要开也在插件管理器搜 "UMG Viewmodel",但本章方案不依赖它。
10. 老教程的 GameplayTagsList 段格式在 5.8 已失效(错题本 P23)。本章不加标签,但若顺手给 UI 相关功能打标签,必须用 [/Script/GameplayTags.GameplayTagsSettings] 段的 +GameplayTagList= 格式。
