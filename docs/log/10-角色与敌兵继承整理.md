# 角色与敌兵继承整理（2026-10-20）

## 完成后的结构

```text
BaseCharacter（现有 C++ 基类，暂留）
└─ BP_CombatCharacter（新增共同蓝图父类）
   ├─ BP_Player（原玩家资产）
   └─ BP_Dummy（原木桩，后续作为近战敌兵）
```

保留原玩家、木桩资产路径，避免地图、GameMode和技能引用改名。没有把玩家输入/HUD提到共同父类，没有创建额外玩家角色。旧 BP_BaseCharacter 路径仍保留，本轮未修复其历史重定向；实际共同父类以 BP_CombatCharacter 为准。

## 各层职责

- BP_CombatCharacter：拥有 CharacterStatsRowName（分类“角色配置”）和 InitializeStatsFromTable；BeginPlay 先从 DT_CharacterStats 初始化生命/体力，再应用 GE_StaminaRegen。双方共用这套流程。
- BP_Player：继承行名变量，默认 Player；原移动输入、攻击/翻滚/跳跃门控、武器注册等玩家逻辑保留。移除了自身重复的数值表变量、初始化函数以及仅用于初始化/回复的 BeginPlay 链，改为继承父类出生流程。三段普攻、翻滚、跳跃五个启动技能原样保留。
- BP_Dummy：继承同一父类，行名 Enemy_Melee；原空 BeginPlay 移除，避免遮挡父类事件。目前仍没有追击、攻击能力或AI，本轮没有声称完成敌兵战斗。

共同父类默认行名为 None；创建其他子类时必须选择有效行。新逻辑未加入存档、等级成长或复活重置。

## 修复的初始化问题

ABaseCharacter::BeginPlay 先调用 Super::BeginPlay（其中会执行蓝图 BeginPlay），后应用旧 InitAttributesEffect。玩家原默认指向 GE_InitAttributes，会在蓝图读表完成后覆盖数值。本轮清空玩家和共同父类的旧 InitAttributesEffect（木桩原本已为空），不修改 C++ 源码。

新 GE 的标签已对应正确，但实机读出顺序仍是 Health、MaxHealth、Stamina、MaxStamina。本轮调整为 MaxHealth、MaxStamina、Health、Stamina，四项 Override + SetByCaller，DurationPolicy=Instant。

## MCP 与 EasyGas 的区别

官方 MCP 是编辑器自动化工具，负责检查资产、建图、接线、编译和测试。EasyGas 是可选 GAS 扩展，使用户能在蓝图定义属性集；二者不是替代关系。MCP 不会自动让原生 GAS 支持蓝图属性定义。

EasyGas 尚未安装或验证UE5.8。用户要求优先免费。现有 MyAttributeSet 和其他 C++ 暂留，属性迁移另行验证后开展；本轮没有声称工程已纯蓝图。
