## 2. 跳跃从直接调用改为 GAS 技能

新增 `GA_Jump`，资产标签 Ability.Jump，ActivationOwnedTags 为 State.Jump，Cost 指向 GE_Cost_Jump。BP_Player 的 StartupAbilities 已包含 GA_Jump，IA_Jump 保留原移动锁门控；未锁时通过自身 ASC 和带 Ability.Jump 的容器请求技能。松开按键继续调用原 Stop Jumping。

技能流程：

```text
ActivateAbility
  → Get Avatar Actor from Actor Info
  → Cast To BP_Player
  → Can Jump → Branch
      False → EndAbility
      True → CommitAbility → Branch
          False → EndAbility
          True → Jump（Target 为角色）
              → WaitMovementModeChange（New Mode = Walking）
                  On Change → EndAbility
```

Cast Failed 也应结束技能。Can Jump 在提交成本前检查，避免明显不能再跳时仍发起扣费；不要把 Branch 的 Condition 留成常量 True。Jump 是 Character 上的真实起跳请求，不是技能上的 Montage Jump to Section。

## 3. 回复配置与生命周期修复

当前 `GE_StaminaRegen` 是 Infinite，Period=0.05 秒，每周期 Stamina +2，即允许回复时名义约 40 点/秒；关闭应用时立即执行周期效果。持续标签要求的排除项为：

- State.Attacking
- State.Rolling
- State.Jump

只要其中任意状态存在，持续回复被抑制。状态消失后恢复周期回复。数值以本表为准，旧日志中的每秒 +1 是历史配置。

最初采用 `Jump → EndAbility`，能完成起跳扣费，但技能立即结束，State.Jump 也立即移除，无法覆盖空中阶段，所以回复 GE 的标签排除看似失效。修复为调用 Jump 后等待移动模式变为 Walking，再从 On Change 结束技能；State.Jump 因而保持到落地。用户明确确认修复成功，记录到 P36。

WaitMovementModeChange 的普通执行输出不用于直接结束技能，必须使用 On Change；不能在松开跳跃键时结束该 GA，否则尚未落地就恢复回复。该实现按当前单次跳跃玩法配置，多段跳、游泳/飞行等后续模式需另行设计，不视为本轮已支持。
