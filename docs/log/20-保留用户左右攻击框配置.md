# 20：尊重用户配置的左右攻击框

用户指出原 GA 在运行时 AttachToComponent + SnapToTarget 覆盖自己配置的左右框位置与范围，明确要求修改。此前实际旧节点引用已随用户重命名指向左框，却仍强制挂到 weapon_r 并清空偏移、旋转、缩放。用户要求原配置是权威来源，不能通过运行时重挂或自动扩大范围替代。

## 修改

- 移除 GA_EnemyAttack 的 AttachToComponent、RegisterWeaponCollision、单框 EnemyHitbox / HitboxRegistered 缓存及分支。没有新增或改造 C++。
- 保留 BP_Dummy 现有 EnemyWeaponHitbox_L / EnemyWeaponHitbox_R：挂 Mesh 的 weapon_l / weapon_r，偏移分别 (0,60,0) / (0,-60,0)，缩放均 (0.2,2,0.25)，BoxExtent均(70,45,100)。旋转保持用户值。本轮不修改以上任一值，不重新挂接。
- BP_Dummy 新增 OpenEnemyAttackWindow / CloseEnemyAttackWindow：只设置 EnemyAttackWindowOpen 与两个框的 CollisionEnabled。默认 NoCollision，窗口内 QueryOnly，生成Overlap事件，响应仅Pawn重叠（这些是检测配置，非几何覆盖）。
- 两个组件的 OnComponentBeginOverlap 各自检查窗口开启且 OtherActor 为 Player0，然后发送共享 Event.Montage.Attack.Hit。
- 新 ANS_EnemyAttackWindow（复制原通知后改为调用怪物专用开关函数），绑定 AM_EnemyAttack 原 EnemyHitWindow 轨道0.30–0.65秒。保留玩家原 ANS_AttackWindow 及其C++单武器链路。
- 怪物 GA 的 WaitGameplayEvent 改 OnlyTriggerOnce=true，单次技能只有一次挥击且事件已过滤Player0，因此两个框同一次攻击都命中也仅施加一次共享 GE_Damage（50）。发动前与 OnEndAbility 关闭两个框，避免残留。
