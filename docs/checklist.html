关键架构决策(回来先读这段)

时间轴即状态机(用户拍板):移动锁、连击窗口、判定区间全部归蒙太奇时间轴上的通知管;GA 只管激活门槛和结算。理由:Activation Owned Tags 只能"GA 活多久锁多久",表达不了"部分帧锁定"和"移动攻击"。

方案甲:GA 在窗口帧自我了结(EndAbility),蒙太奇 StopWhenAbilityEnds=false 继续播。移动锁、父标签阻挡随之解除 → GA_2 凭窗口标签放行。窗口期还能走位(魂系手感)。

两个时间旋钮互相独立:开启帧=蒙太奇上通知的位置;宽限期=GE_ComboWindow_i 的 Duration。蒙太奇播完 ≠ 连段结束。

硬约束:蒙太奇里 判定区间(ANS_AttackWindow)结束帧 必须早于 连击窗口开启帧,否则 GA 先死、命中监听器陪葬。

攻击键输入必须按父标签激活:TryActivateAbilitiesByTag(Ability.Attack.Light),三段 GA 同时被尝试,由条件自动选拔。C++ 的 OnAttackInput 通道确认是死的(AttackAction 为空),不用拆。

移动取消后摇不上 C++(用户拍板,2026-10-09):曾在 BaseCharacter::Move() 里加"窗口期移动 → CancelAbilities",已回滚。理由:① 方案甲里 GA 在窗口帧自我了结,ANS_MoveLock 的结束帧=恢复移动帧,收刀走位天然成立,蒙太奇照常播完;② 想调整"第几帧可走动",动画师拖 ANS 结束帧即可,纯拖帧零代码;③ 符合"GA 只管激活门槛和结算,时间轴管状态"的总架构。已验证引擎 5.8 带 WaitGameplayTagAdd/WaitGameplayTagRemove 任务(仅 GA 图表内可见,BlueprintInternalUseOnly),纯蓝图路线的节点储备在。

验收卡点记录(2026-10-10 redesign)

症状 1 redesign(用户拍板,取代"取消勾选 StopWhenAbilityEnds"的旧建议):攻击是插槽蒙太奇,盖在移动状态机上。GA 在窗口帧自我了结、蒙太奇却继续播 → 移动时上身攻击动画悬空、下身滑步平移,手感错误。正确设计(用户 2026-10-10 定稿):三条时间轴闸门各司其职——①锁移动=State.MoveLocked(ANS_MoveLock 区间);②可打断收刀=移动锁摘掉的帧;③可衔接=State.Combo.Window.i(GE)。GA 活到"自然播完/被下一段顶掉/玩家移动"三者之一才结束,死了才停蒙太奇(Stop When Ability Ends 保持勾选,停止自带混合过渡,移动动画接管全身)。打断触发 = C++ Move() 里"攻击中(State.Attacking)且未锁移动"→ CancelAbilities——输入只有 C++ 输入层看得见,但许可完全在时间轴上;不要用 Combo.Window 当打断触发器,衔接和打断是两个独立闸门。

配套四改:① GA_1/2 窗口链删掉 EndAbility 节点(只留 WaitGameplayEvent → Apply GE);② 播蒙太奇节点的 OnCompleted / OnCancelled / OnInterrupted 都接 EndAbility;③ BlockAbilitiesWithTag 由父级 Ability.Attack.Light 改成自身精确标签(.1/.2/.3)——GA 活过收刀段后,父级阻止会把窗口期激活的 GA_2 挡死;④ 三蒙太奇 ANS_MoveLock 结束帧 = 连击窗口开启帧(移动放行与可收刀点对齐;硬约束升级为:判定区间结束 ≤ MoveLock 结束 = 窗口开启,否则顶段时旧蒙太奇的 ANS 收尾会摘掉新一段的移动锁)。

症状 2 现状:GE_ComboWindow_1/2 授予标签已确认改为 .1/.2(资产取证 + 文件时间吻合),但最近一次 PIE 日志仍然只有 GA_1 激活。剩余嫌疑:GA_2 激活所需标签内容、GE 宽限时长、ANS_MoveLock 帧位。已备编辑器 Python 一键诊断脚本 Saved/diag_gac_config.py,跑一次全部现形。
