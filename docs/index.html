C++ 地基 + 蓝图逻辑技术路线

项目目标：制作一段完整可玩的魂类 ARPG demo——「篝火出发 → 推图清怪 → Boss 战」， 战斗系统基于 Gameplay Ability System (GAS)，作为游戏策划求职作品集的核心 demo。

本文档的双重作用：

  1. 落地执行：按计划表逐章执行，每章记录「做了什么 / 为什么 / 踩了什么坑 / 如何验收」，做完一章填一章。
  2. 长期复习：很久以后忘记做法时，按章节可完整回忆整个工程的运作方式。

设计支柱（最小可行范围，不扩大）

  • 一个角色：Greystone（剑盾骑士），动画库最全：三段普攻 Attack_PrimaryA/B/C、四方向受击、死亡、眩晕、Deflect_InPlace（弹反预留）、RMB_Targeting（锁定姿态）。
  • 一张灰盒小关卡：线性路径 + 一个 Boss 场地 + 一个篝火。
  • 三种敌人：近战小兵 ×N（ParagonMinions）、精英 ×1、Boss ×1（Grux）。
  • 核心循环：锁定 → 观察 → 三连击 / 翻滚（无敌帧）→ 体力管理 → 处决窗口（可选）。

技术决策（已定型）

决策结论理由
工程形态纯蓝图 → 转 C++（保留全部现有资产）GAS 的 AttributeSet 只能 C++ 定义；C++ 工程本身是简历加分项
GAS 参考tranek/GASDocumentation + Narxim 示例照抄骨架社区事实标准；官方文档太薄
ASC 挂载玩家与敌人都挂 Character单机 demo 不需要 PlayerState 方案（多人标准做法，面试能讲即可）
战斗判定AnimNotify 发 GameplayEvent → GA 内球体扫掠 → GE 结算借鉴官方格斗模板链路，改造为 GAS 管线
无敌帧AnimNotifyState 窗口内 Apply 带 State.Invulnerable 的 GE"无敌窗是动画数据不是代码"，策划调帧不改代码

路径规范工程永远保持纯英文路径格斗模板中文路径副本的 DefaultEngine.ini 已损坏，前车之鉴

GAS 心智模型

所有 GAS 概念都能放进这张表。记不住细节时先回来对号入座。

概念缩写干什么策划类比在我们工程里
AbilitySystemComponentASC挂在角色身上的总线：持有属性、技能、效果角色的"战斗大脑"主角/小兵/Boss 各一个（C++ 基类创建）
AttributeSet—定义属性：HP、体力、攻击力Excel 字段定义C++ 类 UMyAttributeSet，唯一必须写 C++ 的部分
GameplayEffectGE修改属性的规则：伤害-50、体力-20、周期性回复一条数值公式 / 一个 Buff纯蓝图资产，策划主战场
GameplayAbilityGA一个技能：普攻连段、翻滚、Boss 招式技能表的一行蓝图 GA：PlayMontage + WaitGameplayEvent 节点链
GameplayTagTag层级标签：状态、事件、技能标识状态标记 / 筛选器Ability.* State.* Event.* 三棵标签树
GameplayCueGC表现层：特效、音效、震屏表现配置表命中火花、受击音效
AbilityTask—GA 里的异步节点：播动画、等事件、等输入技能流程的步骤蓝图节点，连线即用

一次攻击的完整管线（魂游 demo 版）

玩家按 LMB
  → Enhanced Input 触发
  → RequestAttack → ASC.TryActivateAbilitiesByTag(Ability.Attack.Light)
  → GA 检查条件并 CommitAbility(检查并应用 Cost GE)
  → GA 播放 Attack_PrimaryA 蒙太奇
  → ANS_AttackWindow 开启武器碰撞,重叠命中后发送 GameplayEvent (Event.Montage.Attack.Hit)
  → GA 的 WaitGameplayEvent 收到带目标的 TargetData
  → 命中敌人 → ApplyGameplayEffectToTarget(GE_Damage)
  → 敌人 ASC 结算：查 State.Invulnerable → 扣血 → PostGameplayEffectExecute
  → 血 ≤ 0 → 打 State.Dead 标签 → 播死亡动画
  → 命中表现走 GameplayCue（火花/音效/震屏）
面试话术：伤害结算、Buff、冷却、消耗全部走同一套 GE 管线，策划改数值不动代码，网络同步天然支持——这就是用 GAS 而不是 ApplyDamage 的理由。

第 0 章 · 备份与版本管理 完成

目标

工程纳入 git，建立可回滚的基线；轻量部分（代码/文档/配置）推 GitHub 公开仓库，作为简历可附的代码链接。

最终架构：嵌套双仓库（重要，先理解再操作）

初始盘点将整个 Content 视为约 19GB 的本地素材库，因此采用嵌套仓库。2026-10-18 换机复现盘点后，已确认大部分体积来自可重新获取的 Paragon 包；当前 GitHub 同步的是工程自有资产快照，而非完整 Marketplace 素材库。

  • 外层仓库（工程根目录 .git）：跟踪 Source/ docs/ Config/ .uproject .gitignore 等轻量文件，.gitignore 里排除 Content/ 与引擎缓存。这个仓库推 GitHub，体积小、公开无压力。
  • 内层仓库（Content/.git）：本地跟踪完整工作副本与素材历史；其中 Paragon 原始资源包不上传 GitHub。

外层仓库保留代码、配置和文档，并额外包含 ProjectContentSnapshot/Content/：筛选后的工程自有蓝图、输入、地图与外置 Actor 数据。换机时先重新取得 Paragon 依赖，再运行 Tools/Restore-ProjectContent.ps1。详情见 资产盘点与干净环境恢复。

日常口诀：改代码/文档或自有资产快照 → 根目录 commit；动完整素材工作副本 → Content 目录本地 commit；Paragon 原始资源不推 GitHub。

已执行步骤

  1. git config --global core.longpaths true（Windows 必须，UE 路径很深）
  2. .gitattributes：uasset/umap 标记 binary，防止换行符转换污染资产
  3. 外层：git init -b main → 基线提交（uproject + Config + docs）
  4. 内层：cd Content && git init -b main → 本地素材历史(包含 Paragon 资源包)
  5. GitHub：创建空公开仓库 → git remote add origin → push -u origin main（首次推送 Git Credential Manager 弹浏览器授权）

验收

外层 git status 干净且不含完整 Content；内层素材历史保存在本地；GitHub 当前保存 195 个工程自有内容资产快照，可按文档恢复。

第 1 章 · 工程 C++ 化 完成

目标

纯蓝图工程变为 C++ 工程：出现 Source/ 目录，编译通过，编辑器照常打开，不动任何现有资产。

知识点：这一步到底发生了什么

  • UE 工程 = 若干"模块(Module)"，每个模块 ≈ C# 的一个程序集(Assembly)。引擎本身是几百个模块；我们的游戏加一个叫 ProjectUnreal 的模块。
  • Source/ProjectUnreal/ProjectUnreal.Build.cs：模块的"项目文件"，声明依赖哪些引擎模块（类似 .csproj 的引用）。
  • UBT(UnrealBuildTool)：UE 的构建系统，读 Build.cs 调 MSVC 编译出 dll，编辑器启动时加载。
  • .uproject 里会多出 "Modules" 声明——这是纯蓝图与 C++ 工程的唯一文件级区别。

步骤（先讲后做，逐条确认）

  1. 编辑器内 Tools → New C++ Class → 选 None 类，命名 ProjectUnrealBootstrap（仅用于触发工程转换，事后可留可删）。
  2. UBT 自动生成 Source、.sln，弹出编译。
  3. 编译失败排查：确认 VS2022 已装"使用 C++ 的游戏开发"负载（启动日已确认 MSVC 在）。
  4. 编译通过后关闭编辑器，验证双击 .uproject 能正常启动。
  5. git commit。
退路：若编译彻底失败，删除 Source/、Binaries/、Intermediate/ 及 .uproject 的 Modules 段（或 git 回滚），工程立即退回纯蓝图，资产无损。

验收

编辑器正常打开，Content 资产完整，PIE 可运行。

第 5 章 · 体力 / 翻滚 / 无敌帧 进行中

目标

魂游三要素成型：体力循环（消耗+回复）、翻滚位移、无敌帧免伤、受击硬直与死亡。

要点

  • 体力回复：Periodic GE（每 0.1s +x），或用 Duration GE + 延迟回复（魂游是"停止消耗后约 1s 开始回"——用 GE 的 GrantedTag State.Stamina.RegenBlock 抑制回复是标准做法）。
  • 翻滚第一版已完成：Mixamo Stand To Roll 重定向到 Greystone；GA_Roll 播放 AM_Roll，左 Shift 输入，UpperBody 插槽，蒙太奇 Rate Scale=2。当前序列关闭根运动、开启强制根锁定，ANS_AttackLungeWindow 驱动位移。移动取消和攻击取消分别由时间轴窗口配置。
  • 无敌帧：翻滚蒙太奇上 AnimNotifyState 窗口内 Apply GE_State_Invulnerable（GrantedTag: State.Invulnerable）；GE_Damage 配置 Application Immunity 检查该 Tag——免伤在结算层统一生效，任何伤害源都躲得掉。参考：i-frames 专题。
  • 受击：被击 → GA_HitReact 播四方向受击动画（按伤害来源方位选）。
  • 死亡：PostGameplayEffectExecute 检测 HP≤0 → 打 State.Dead → GA_Death 播 Death 动画 → 禁用输入/碰撞。

验收

木桩测试：翻滚穿过攻击不掉血；体力打空后无法翻滚；连续受击有硬直；HP 归零正确死亡。
