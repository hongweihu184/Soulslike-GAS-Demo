# 战斗系统策划案 · 魂类 ARPG Demo

> 版本 v0.8(2026-10-17)｜作者:策划 + AI 结对
> 本文档是**设计决策的契约**:每个规则写清"是什么、为什么、我们选择了哪条路"。
> 非通用常识,而是**本项目自己的要求**——别家游戏的做法只是参考。

## 0. 设计支柱(不可动摇)

1. **魂系手感**:每一次输入都有承诺(前摇必出、后摇真实、体力有限)
2. **策划即配置**:战斗的一切数值/时机/规则都在资产里(GE/GA/蒙太奇轨道),不在代码里
3. **代码是执行器,不是阀门**:代码只负责"标签语义怎么执行"(锁→吞输入、收刀→取消技能),**永不内嵌政策**(什么时候锁/什么时候收/什么时候衔接)。代码是可插拔的黑箱组件,政策全部在配置侧的时间轴上。反例与事故见 P25/P26(docs/reference/troubleshooting.html):政策写进代码 = 策划失去控制 = 项目成果随机,最终必崩
4. **最小闭环优先**:先砍出第一剑,再谈华丽

## 3. 攻击系统

### 3.1 普攻三连击
- 三段:Attack_PrimaryA → B → C(Greystone 素材)
- 伤害管线:武器胶囊 overlap → 命中事件(带目标)→ GA → GE_Damage → Damage 元属性通道 → 扣血
- **命中判定 = 武器真实扫过空间**(剑刃骨骼 sword_bottom→sword_top 胶囊,跟随动画);判定区间是蒙太奇轨道上可拖的通知状态(ANS_AttackWindow)
- 一刀一名单:同一挥击同一目标只命中一次

### 3.2 连击规则(本项目自定义,非通用)
- 攻击期间**不接新普攻**(同类技能不可重入,引擎天然行为)
- 命中后/后摇中开启**连击窗口**(轨道上可拖的通知 + GE_ComboWindow 授予 State.Combo.Window,0.5s)
- 窗口内输入 → 激活下一段(GA_2/3 的激活所需标签 = State.Combo.Window,窗口外静默失败)
- 窗口后接 → 取消上一段,播下一段

### 3.2b 后摇保护:阻止矩阵(P25 设计,必配)

**语义**:"阻止别的技能(BlockAbilitiesWithTag)" = 本技能存活期间,带这些标签的技能**禁止激活**。
**原则**:连击 = 窗口期放行兄弟 + 非窗口期封死全家,两者缺一不可;只配前者,末段后摇必被自己人抢跑腰斩。

| 技能 | 阻止别的技能 | 效果 |
|---|---|---|
| GA_1 | `Ability.Attack.Light.1` | 拦自己重开;窗口期放行 GA_2/GA_3 |
| GA_2 | `.1` + `.2` | 拦 GA_1 抢跑 + 拦自己;放行 GA_3 |
| GA_3 | `.1` + `.2` + `.3` | 末段封全家,后摇完整播完才解锁 |

> GA_3 用**显式子标签逐个封**(2026-10-13 拍板,不用父级一刀切):新增一段时,把 `.4` 加进 GA_3 的阻止列表即可——显式列出 = 每段衔接关系策划亲手可控;代价是加新段要回头改 GA_3,作为契约接受。

### 3.3 体力(消耗已实装,回复待定)

- 空中禁普攻使用虚幻自带功能配置实现,自定义 C++ IsAirborne 已按用户要求删除(2026-10-17 确认)。
- 每段普攻 -20(GE_Cost 挂在 GA 的 Cost 上,2026-10-15 经 P27 补 CommitAbility 后正式生效)
- **铁律:GA 激活图必须调 CommitAbility**——Cost/Cooldown 由 Commit 统一执行(检查+扣款),只激活不 Commit = 资源永不消耗。Commit 失败支(体力不足)必须 EndAbility 退场
- 体力 100 起步,消耗节奏 = 连打 5 段空体;空体后激活被 Commit 静默拒绝(引擎白送,不用自己写)

## 4. 输入门控(移动锁与收刀,情景模型 + MoveCancelWindow,2026-10-13 定稿)

### 三情景模型(本项目攻击期间移动的全部语义)

攻击从激活到播完,移动输入处于且只处于三种情景之一:

| 情景 | 时段 | 移动的行为 | 判别 |
|---|---|---|---|
| **1 激活保护** | GA 激活 → 锁段开始 | **放行不动**:不打断技能,正常给移动(或由锁段快速接管) | 没有 `State.MoveLocked`、没有 `State.MoveCancelWindow` |
| **2 锁段** | ANS_MoveLock 区间 | **吞输入**:移动/跳跃完全禁止 | `State.MoveLocked` 存在 |
| **3 收刀窗** | 锁段结束 → 蒙太奇结束 | **收刀**:按移动取消技能,状态机动画接管 | `State.MoveCancelWindow` 存在(且未锁) |

**核心矛盾**:情景1和情景3在现象上都是"攻击中、未锁移动"——只看这两个标签永远无法区分,政策必然写成跷跷板(修 A 出 B)。**区分它们的唯一正确方式是第三条轨道**:蒙太奇上的 `ANS_MoveCancelWindow` 区间(→ GE → `State.MoveCancelWindow`)。窗口开始前标签不存在 → 情景1天然免疫收刀;窗口存在 → 情景3收刀。判别器本身变成策划手可拖的帧。

### 设计决策(重要,本项目自选规则)
- 普攻期间**锁定移动与跳跃**,锁段 = ANS_MoveLock 的区间(→ GE_MoveLock → State.MoveLocked)
- **移动可以收刀**:锁段结束后按方向键取消攻击,收刀窗 = `ANS_MoveCancelWindow` 的区间,起点就是收刀点
- **技能可以覆盖普攻**(打断并接管)——不是所有游戏都有这个说法,这是我们的要求
- **技能不一定锁移动**:锁不锁由每个技能自己配不配 GE_MoveLock 决定,与技能强度无关
- 锁/窗的解除 = GE 到期自动解除(时长制,不靠命令式开关)

### 政策层(BP_Player 事件图,策划可见可改)与能力层(C++,零政策)

```
IA_Move → IsMoveLocked? ──True→ 吞(情景2)
              └─False→ Has State.MoveCancelWindow? ──True→ CancelAttack → Move2D(情景3)
                                  └─False→ Move2D(情景1,放行不动)
IA_Jump Started → IsMoveLocked? ──False→ RequestJump
```

C++ 只提供**纯动词**(RequestAttack / CancelAttack / RequestJump / Move2D / Look2D)和**纯查询**(IsMoveLocked / IsAttacking,以及 ASC 自带的 HasMatchingGameplayTag)。**没有任何 C++ 状态机**——早期版本用 `bAttackLockApplied` 标志位当判别器,逻辑等价但住在代码里策划看不见,已废弃。

### 架构铁律(为什么不能写进代码)
教训一(P26):把"收刀政策"写在 Move() 回调里每帧轮询("攻击中 && 没锁 → 收刀"),GA 激活到 ANS 打标签之间的空窗会误杀激活 → 站着能砍、按着走永远挥不出刀。
教训二(P26 后续):把判别器做成 C++ 标志位,逻辑对但不可见,调手感时成为"幽灵变量"。
**定案:三情景全部由轨道标签表达,代码只执行无条件翻译。**

### 引擎语义备忘(踩过坑,别再踩)
- **取消技能 ≠ 蒙太奇停下**。`UAbilityTask_PlayMontageAndWait` 只在 `Stop When Ability Ends` 勾选时才会随技能结束停蒙太奇(引擎 OnDestroy 源码:`if (AbilityEnded && bStopWhenAbilityEnds) StopPlayingMontage()`)。没勾 = 收刀后动画播完 = 滑步/幽灵动画。三个 GA 的该选项必须勾。
- 连击顶段走**同插槽蒙太奇顶替**,不经由取消,与该选项无关——勾选不影响连击。

### 策划调参契约(改手感 = 改配置,不动代码)
| 手感 | 调哪里 |
|---|---|
| 冻结窗口(攻击中不可动) | ANS_MoveLock 区间的起点和长度 |
| 收刀点(之后按方向键收刀) | **ANS_MoveCancelWindow 的起点**(终点一般到蒙太奇末尾) |
| 可衔接下一段的时机 | GE_ComboWindow 的授予帧 + 0.5s 宽限 |
| 攻击前几帧允许跑动衔接 | ANS_MoveLock 起点后移;极端做法是从第 0 帧就铺 MoveCancelWindow(锁段判断优先,不冲突) |

### 层级查询原则
任何系统要查"是否锁移动",读 `State.MoveLocked`;要查"是否可收刀",读 `State.MoveCancelWindow`;要查"是否在攻击",读 `State.Attacking`。
**规则在 GE/轨道(策划),查询在标签(任何人),执行在通用闸门(代码一次写好不含规则)。**

### 4.6 攻击蒙太奇时间轴解剖(一段普攻的完整轨道)

```
0                 锁段结束(=收刀点)                      播完
|──[ANS_MoveLock]──|────────────[ANS_MoveCancelWindow]──────────→
        |──[ANS_AttackWindow]──|
                     ⚑ Event.Combo.WindowOpen
```

| 轨道元素 | 产生什么 | 谁消费 | 存在的理由 |
|---|---|---|---|
| ⚑ Event.Combo.WindowOpen | 一次性消息,当帧即焚 | 本段 GA 听到 → 贴 `State.Combo.Window.N`(宽限 0.5s) → 下一段 GA 激活所需标签匹配 | **衔接许可**。"我是第几段"的知识只能住 GA:三段蒙太奇发同一个消息,GA_1 听到贴 .1、GA_2 听到贴 .2;将来加第四段,蒙太奇一个字不用改 |
| ◆ ANS_AttackWindow | 开/关武器碰撞盒 | 武器 overlap 时 C++ 发 `Event.Montage.Attack.Hit`(带目标) → GA → GE_Damage | **判定 = 剑真实扫过空间**。窗口可拖 = 判定区间可拖;一刀一名单,防一次挥击多次扣血 |
| ◆ ANS_MoveLock | `State.MoveLocked` | BP_Player 移动/跳跃分支 | **情景2:攻击有重量**。前摇冻结期吞一切移动输入,区间帧位即手感 |
| ◆ ANS_MoveCancelWindow | `State.MoveCancelWindow` | BP_Player 移动分支 | **情景3:后摇可收刀**。起点 = 收刀点;它同时是情景1/情景3的判别器——窗口存在才可收刀,不存在就是激活保护期 |

四元素覆盖一次攻击的完整生命周期:**冻结(锁)→ 判定(窗口)→ 放行衔接(消息)→ 可取消收尾(收刀窗)**。
锁段结束帧与收刀窗起点是同一个点;拖任意一个,另一个按邻居对齐。

## 10. 标签体系:三类标签各管一件事(图解)

> 本节写给一个月后的自己。标签系统最容易绕晕的点:同样是 GameplayTag,为什么有的当"消息"发、有的当"状态"挂?绕进去的时候回来读这节。

### 10.1 一句话版

**Event 是一次性消息,State 是挂在身上的状态,Ability 是技能的身份证。蒙太奇只许发消息,永远不许碰状态。**

### 10.2 三类标签分工表

| 类别 | 本项目的例子 | 本质 | 寿命 | 谁产生 | 谁消费 |
|---|---|---|---|---|---|
| `Event.*` | Event.Combo.WindowOpen、Event.Montage.Attack.Hit | 一次性消息:"某事刚发生了" | 当帧即焚 | 蒙太奇通知 / C++ | GA 的 WaitGameplayEvent |
| `State.*` | State.MoveLocked、State.Combo.Window.1 | 持续状态:"正处于 XX 中" | 有时长,自动过期或被摘除 | GE(挂在角色 ASC 上) | 激活条件、移动闸门等一切查询方 |
| `Ability.*` | Ability.Attack.Light.1/.2/.3 | 技能身份证:"这技能是谁" | 永久(类默认值静态配置) | GA 资产 | 激活/阻挡/取消的标签匹配 |

命名直觉:Event 用"发生过的事"(WindowOpen=窗口开了),State 用"进行中的事"(Window=窗口开放中、MoveLocked=移动锁定中)。

### 10.3 信息流全景图(三连击第一段为例)

```
蒙太奇A时间轴: ──[判定区间]────[命中帧]──────[窗口帧]──────────[画面播完]
                    │              │              │
                    │              │              └─ AN_SendGameplayEvent 发消息
                    │              │                 Event.Combo.WindowOpen(当帧即焚)
                    │              │                    │
                    │              │                    ↓ GA_1 的 WaitGameplayEvent 听到
                    │              │                 ① ApplyGameplayEffectToOwner(GE_ComboWindow_1)
                    │              │                    → 角色贴上 State.Combo.Window.1(宽限几秒,自动过期)
                    │              │                 ② GA_1 继续存活,窗口事件不立即 EndAbility
                    │              │                    → 移动锁/收刀窗由 ANS 管理,阻挡随 GA 生命周期管理
                    │              │                 ③ 宽限期内玩家按攻击键
                    │              │                    → GA_2 激活条件"身上有 State.Combo.Window.1"✓ → 激活
                    │              │
                    │              └─ 武器碰撞盒 overlap → C++ 发消息
                    │                 Event.Montage.Attack.Hit(带目标句柄)
                    │                    │

                    │                 → ApplyGameplayEffectToTarget(GE_Damage) → 木桩扣血

```

### 10.4 职责边界(每个部件只知道它该知道的)

```
蒙太奇  报告事实  ──"播到某一帧了"(发 Event,不知道自己是第几段)
GA      解释事实  ──"窗口帧意味着我该贴 Window.1;结束由完成/打断/取消决定"(听 Event,做决策)
GE      管理状态  ──"State 贴多久、什么时候自动撕掉"(时长/宽限期全在 GE)
查询方  只看状态  ──激活条件/移动闸门只读 State.*,永远不读 Event
```

### 10.5 自问自答(绕晕时查)

- **Q:蒙太奇为什么不直接发 State.Combo.Window.1?**
  A:两层原因。① SendGameplayEvent 这个节点发的是"消息",塞状态标签进去属于类型能填、语义错误;② 更根本的——"我是第几段"这个知识**只能住在 GA 里**。三段蒙太奇发同一个消息 Event.Combo.WindowOpen,GA_1 听到贴 .1、GA_2 听到贴 .2。将来加第四段,蒙太奇一个字不用改,只加 GA_4。
- **Q:State 贴纸怎么消失?要手动摘吗?**
  A:不用。GE 有时长,到期自动撕(State.Combo.Window.1 的宽限期就是这么实现的);ANS 区间类的(如 MoveLock)由通知状态在区间结束时摘除。
- **Q:我要查"现在能不能移动/能不能接下一段",看哪个?**
  A:只看 State.*。Event 是历史上发生过的事,不代表现在。
- **Q:预览日志里出现过通知发 None / 发 State 的报错?**
  A:那是编辑过程中的瞬时值,以存档文件为准。2026-10-08 实测:蒙太奇 A 存档里只有一个通知、标签为 Event.Combo.WindowOpen,正确。
