# 设计判断记录

用于记录有复用价值的真实决策。按需要填写，未知内容写“待确认”，不要替用户补写理由。

- 编号与日期：
- 问题、发生场景与约束：
- 用户希望达成的体验或玩家行为：
- 来源：可定位的对话、文档段落或试玩记录；注明原话或转述。
- 候选方案及其取舍：
- 用户的选择与其明确说明的理由：
- 助手原先的理解，以及用户如何纠正：
- 待确认的助手推断：
- 验证方法与观察结果：未执行则明确写未执行。
- 候选原则、适用条件与反例：无足够依据时暂不提炼。
- 状态：用户是否确认表达准确；是否有实践支持；仍待解决的问题。
- 后续修正及原因：

“用户选择某个参数”只证明这次选择；“用户认可原则”只证明表达获认可；“一次试玩有效”只支持当时条件下的观察。三者不可互相替代。
